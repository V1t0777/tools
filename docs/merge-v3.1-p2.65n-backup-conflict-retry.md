# 《云屿百物铺》V3.1 · P2.65n 恢复备份槽冲突后的普通模式可用性（未发布）

## P0 缺陷与边界

恢复前备份槽已有不同原始字节时，第二次导入会在 `prepareNormalSaveRestoreBackup` 的只读槽检查处返回 `BACKUP_SLOT_CONFLICT`，该分支尚未执行任何备份或主存档写入。此前普通模式的单飞门禁把该确定的“未写入拒绝”当作未知写入结果，永久阻断玩家正常经营；用户即使只是在导入对话框里尝试第二个文件，也会被迫重新加载页面。

本轮仅将**精确的** `BACKUP_SLOT_CONFLICT` 列为安全无写入拒绝，保留提示“恢复前备份槽已存在不同内容，请先导出并核对备份”。绝不覆盖或清除旧备份，绝不自动重试导入，也不放宽任何存档基线、Web Locks、确认或恢复写回检查。

`BACKUP_OR_SAVE_CHANGED`、`BACKUP_VERIFY_FAILED`、`BACKUP_CHANGED`、`CURRENT_SAVE_CHANGED`、`RESTORE_OUTCOME_UNCERTAIN` 等依旧严格阻断，因为这些结果可能表示并发修改、部分备份写入或结果不明。分类依据为现有 `save-restore-backup.mjs` 的实际执行顺序，而不是凭错误名称猜测。

## 验证

- 单飞门禁测试：备份槽冲突可继续；备份部分写入或校验失败仍阻断。
- 运行时测试：已有不同备份拒绝恢复但仍可正常执行玩家动作；连续两次导入不能覆盖首次恢复前原始证据。
- 真实普通模式 HTML 入口 DOM 模拟：首次导入成功，第二次导入冲突不写主档、不改备份、不碰剧情键；随后普通模式操作仍能保存。
- 提交后须核对**最终 SHA** 的全仓库 Node 回归、`bash scripts/security-check.sh`、完整历史密钥扫描以及是否出现 Cloudflare 部署；未全绿不得标记完成。

## 剩余风险与发行限制

备份槽不允许静默轮换；用户需自行导出并核对原始备份，后续若要支持备份归档或清理必须另行设计可审计的显式流程。本轮不提供该能力。Web Locks 不是跨设备事务，旧版本不合作标签仍可能并发写入；iPhone Safari、微信 WebView、下载落盘及真实浏览器双标签尚未实测。Cloudflare Pages 后台状态无法独立核验。PR #58/#59 均保持 Draft；不合并 main、不发布、不改导航/白名单、不操作线上 Supabase。11 月 10 日仅依据验收证据提出候选建议，发布须用户额外明确授权。
