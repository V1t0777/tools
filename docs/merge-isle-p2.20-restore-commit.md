# 《云屿百物铺》P2.20 — 普通模式本地恢复提交与读回校验（未发布）

## 本轮实现

新增 `merge/save-restore-commit.mjs` 的 `commitNormalSaveRestore(fileText, storage, {expectedRaw, confirmed, allowDowngrade})`。**独立研发模块，未接入游戏 UI**，不存在自动恢复、导入按钮或线上数据库调用。

1. 仅当调用方确实取得用户确认并传入 `confirmed:true` 才进入预检。布尔值不是用户真实授权的证明；正式界面仍需独立实现确认步骤。
2. 重新校验文件是合法 V3 普通模式存档、当前存档和已观测 `expectedRaw` 完全一致。进度修订号降低时还必须明确设置 `allowDowngrade:true`，默认拒绝。
3. 调用 P2.19 创建或复用已验证的独立原始存档备份；备份槽冲突、容量/写入错误均拒绝继续。
4. 备份完成后再运行完整预检，重新检查备份槽及原始存档；仅在全部条件成立时写入经过验证的原始候选文件文本，随后读回比对。
5. 读回不一致、写入异常时不宣称成功，不自动删除备份或二次覆盖存档。成功结果只返回版本、修订号与备份状态，不回显背包、金币或原始存档字节。

## 本轮专项回归

`tests/merge-save-restore-commit.test.mjs` 覆盖：缺失确认、正常恢复、无旧存档、回退二次确认、损坏文件、过期基线、备份冲突、备份阶段的跨标签修改、备份被抢占、存储异常、写入后读回不一致、剧情模式隔离、UI 未接入。

## 重要残余风险与 RC 门禁

- `localStorage` 的读取、备份写入、主存档写入和读回验证并非原子事务。即使读回成功，也不能排除之后另一标签页的并发写入；不能宣称跨标签事务安全。后续需要评估 Web Locks 或其他受支持的协调机制，并提供实际浏览器竞态测试。
- 备份仍保存在同一浏览器同一 origin 的本地存储；清理站点数据、浏览器存储驱逐或设备故障可同时损失原存档与备份，不能替代外部文件备份。
- 恢复后需要由 UI 主动刷新内存态及持久化基线，否则旧页面可能继续持有过时状态。尚未设计用户确认/导入界面，不能作为可验收的正式恢复功能。
- 尚未开展 iPhone Safari/微信 WebView 真机、断电/容量边界、跨设备和真实 PostgreSQL/Edge 验收。所有经济、背包和进度只在本地处理，不具备云端资产授权。
