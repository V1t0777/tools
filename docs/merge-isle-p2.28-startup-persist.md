# 《云屿百物铺》V3 · P2.28 启动首次保存与迁移状态一致性（未发布）

## 本轮修复
此前页面启动时无条件调用 `persist(); render();`，即使 `loadLocal` 已因备份失败、迁移写入无法确认、损坏存档而返回 `blocked`，仍再次尝试写入；且启动时先执行 `advanceTime`，若首次保存失败，画面可能显示尚未持久化的体力/工坊恢复。

- 新增 `merge/startup-persist.mjs`：只在首次无存档或确有体力/工坊恢复变化时尝试保存；已恢复且没有变化的 V3 存档保持原始字节不重复写入；`blocked` 一律不做自动写入。
- 启动体力恢复仅在 P2.26 精确写入后读回确认成功时才进入玩家内存状态；失败保留 `loadLocal` 的原始内存状态、原始字节基线和暂停标记，不自动重试或回滚。
- `merge/main.mjs` 使用已核验的启动结果，去除末尾无条件 `persist()`；旧版迁移成功提示只在非 blocked 时出现。
- 新增 `tests/merge-startup-persist.test.mjs`：覆盖无变化不写、首次初始化、体力恢复、竞争标签、静默写入失败、损坏存档、旧版备份失败、迁移校验失败与剧情模式隔离。

## 边界与待解决问题
本轮没有把启动迁移改成 Web Locks 事务；`localStorage` 仍然是非原子读写，未参与锁协议的旧标签仍可产生竞态。真实 Safari/微信 WebView、双标签故障测试仍待验收。异常数据仅在玩家明确确认重置后才可能覆盖。不能以 Node 模拟测试冒充实机验收。
