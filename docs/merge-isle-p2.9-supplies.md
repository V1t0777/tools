# 《云屿百物铺》P2.9 — 海风补给、一次性成就与限量商店（未发布）

## 产品范围与参数

- **体力上限**：80 → 120，继续沿用每 180 秒自然恢复 1 点的既有速率，不修改生产成本。
- **背包消耗品**：海风汽水（+25 体力）、海岛便当（+60 体力）、工坊加速卡（所选生产器剩余冷却时间减半）、星辉重启卡（立即结束所选生产器的一次冷却）。
- 满体力禁止使用恢复品；没有正在冷却的工坊时禁止使用冷却卡；拒绝无效目标、缺少物品、非数字时间，不扣库存和 revision。体力恢复不超过 120。
- **一次性成就**：累计交付第 3 单获汽水×1；第 6 单获加速卡×1；累计合成第 30 次获便当×1；交付第 20 单获重启卡×1。使用明确的持久化计数器和 0/1 完成标记，重复操作不能再次领取。
- **金币商店**：汽水 90 金币/限购 4、便当 210/限购 1、加速卡 120/限购 3、重启卡 260/限购 1；限额是**每份本地存档永久限购**，不得通过修改系统时间每日重置。每次成功购买恰好扣除金币、增加一件道具、一次购买计数和 revision。
- 物品图标为现有 emoji 占位，不在此窗口开发手绘美术；没有加入作弊码/无限体力后门。

## 本地存档 V3 迁移

- `schemaVersion` 从 2 升到 3，原始 localStorage 主键 `toolbox.merge-isle.local.v1` 保持不变。
- V1 → V3 的旧版迁移继续使用 `.backup-v1`；V2 → V3 先对原始字节做严格旧规则校验，之后必须成功创建并核对 `.backup-v2` 的**逐字节一致**副本，才允许原位替换。若备份冲突、不可写、主键中途变化或迁移写入失败，则阻断并保留原始字节。
- V2 历史体力不能超过原上限 80。已有棋盘、原料 ID、金币、经验、订单、revision 和原有恢复时间不变；新增道具、成就进度、限购计数都从 0 开始。**过往 P1/P2 委托和合成次数没有可信计数，因此不追溯补发奖励。**
- 本地快照仍是不可信的离线试玩数据，不允许作为未来服务端经济权益依据。P3 云存档模块尚未与页面接线；服务端状态模式迁移及权限协议须另行评审。

## 自动回归及经济验证

- `tests/merge-supplies.test.mjs`：四种道具、合法/非法冷却目标、满体力不消耗、升级/领奖唯一性、商店限额与币值守恒、存档字段边界。
- `tests/merge-supplies-migration.test.mjs`：V1/V2 原字节备份、V2 独立备份、恶意或损坏旧档拒绝、迁移写入故障、并发本地变更、有效新档恢复。
- `tests/merge-supply-economy.test.mjs`：多种固定随机种子的 30 日正常、90 日高频经济仿真，同种子完全可复现。独立核对 `金币余额=委托收入-商店花费`、`库存+消耗=成就发放+购买量`、每物限购与成就至多 1 次、每轮动作上界。
- `node scripts/merge-supply-economy-sim.mjs` 输出 JSON 报告，无网络/数据库操作，不包含真实用户数据。模拟结果仅是合成经济模型的压力验证，不能代替 Windows/iPhone 实际点击、WebKit 兼容或跨设备测试。
