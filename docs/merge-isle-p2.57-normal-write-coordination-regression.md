# 《云屿百物铺》V3 · P2.57 跨事务协调专项回归（未发布）

## 本轮解决的验证缺口
P2.45–P2.56 已实现普通模式持锁启动、操作、计时器、重置和异步 UI 门禁，但以前的专项测试主要分别测试各事务模块，未在**同一个存储对象与同一把 Web Lock** 下验证真实动作顺序。接入实际页面之前，需要证明旧标签的原始字节基线不会跨动作、计时器、重置被错误继续使用。

## 小范围非美术增量
只增加 `tests/merge-normal-write-coordination.test.mjs` 与本说明，**不修改实际页面、运行时代码、存档结构或部署构建**。四个组合测试：
1. 使用真实 V3 引擎，按启动→移动棋盘→体力恢复→确认重置顺序执行；每次旧 `expectedRaw` 都必须被拒绝，并验证剧情模式原始内容不变。
2. 另一个事务占有相同的独占锁时，启动、游戏动作、计时器、重置都立即拒绝（无队列重放），且不读写旧状态。
3. 游戏动作和计时器在同一时刻尝试提交同一原始基线时，最多一次写入，另一个请求返回锁忙；等待锁释放后用旧基线仍被拒绝。
4. 存档损坏时，其他事务持锁期间不得创建重置备份或覆盖存档；锁释放后仅允许先备份并精确读回、再确认重置。剧情模式仍保持隔离。
