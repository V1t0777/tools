# P2.65bn｜确认重置单飞、锁竞争与发布时序回归（2026-10-29）

## 发行阻塞与本轮范围

普通经营模式的重置按钮在用户确认后仍需独占 Web Lock、保全原始备份、核验新存档，并同步发布到 UI。上一轮 P2.65bm 覆盖了锁等待和备份预约期间的页面失效及外部写入；本轮补齐锁忙后的安全重试、重置等待期间的旧操作抑制、正式存档写入后的非合作标签覆盖，以及 UI 同步回调期间的再次覆盖。

新增 `tests/merge-normal-reset-singleflight-publication.test.mjs` 四项确定性故障注入，使用真实 `createNormalPageRuntime`、`commitNormalResetWithLock`、备份预检与存档读回校验，仅将 Web Lock 授予时机、非合作标签写入和同步 UI 回调设为可控。

1. Web Lock 忙时返回 `SAVE_LOCK_BUSY`，不写存档、不占用备份、不阻断正常页面；锁释放后需重新明确执行重置，成功后原始备份字节与新存档均可读回。
2. 已确认重置等待锁时，旧经营动作、计时器和第二次重置必须被单飞门禁拒绝；锁到达后只有原先获授权的重置可写入。
3. 非合作标签在重置存档 `setItem` 后立即覆盖同一键：即使旧写入曾返回成功，读回不同必须拒绝发布，保留竞争标签字节及原始备份，阻断后续写入。
4. 同步 UI 发布回调重入修改原始存档：不得返回成功重置收据，必须阻断页面并要求重新打开核验。

所有场景都检查剧情存档与独立恢复前备份不受影响；允许已安全写入的异常重置原始备份保留，禁止为恢复测试绿灯而删除它。测试不修改正式运行时、经济数值、页面入口、云服务或剧情文件。

## 证据与限制

本轮属于确定性 Node 事务级测试，不能代替 Chromium 双标签、BFCache、iPhone Safari、微信 WebView 的真实生命周期与原生文件落盘。必须对本轮最终 SHA 核验全仓库 Node、`bash scripts/security-check.sh`/部署隔离及完整 Git 历史密钥扫描，不能借用上一个 SHA 的 CI。Cloudflare Pages 后台实际部署状态若无独立证据，继续保留风险。
