# 《云屿百物铺》V3 · P2.53 在途事务失效后的永久阻断（未接入、未发布）

## 安全问题
P2.50/P2.52 的 `createNormalUiFlight().invalidate()` 通过 epoch 阻止旧事务结果发布，但若在途事务已实际写入存档，`run()` 仅返回 `UI_TRANSACTION_INVALIDATED`，门禁仍可继续接受新操作。调用方不能将“未发布界面状态”误当作“未写入存储”。尤其跨标签存档变更、页面隐藏、手势取消等失效可能发生在写入完成和回调发布之间。

## 本轮单一增量
修改 `merge/normal-ui-flight.mjs`：在途事务完成后发现 epoch 已改变时，先永久阻断门禁，再返回原有 `UI_TRANSACTION_INVALIDATED`。阻断对成功回执、已知写前拒绝、异常回执均保守生效，因为调用方此时尚未重新核验真实存档和页面状态。此处不自动重试、不读取或覆盖存档；必须重新打开页面并重新校验真实存档。无在途事务时调用 `invalidate()` 仍是临时失效，不会永久阻断。

## 专项回归
在 `tests/merge-normal-ui-flight.test.mjs` 增加三项测试：失效中的成功写入不能发布且不能再次执行动作；失效中的写前拒绝同样保守阻断；空闲失效仍可重新运行，而永久阻断不能被再次 `invalidate()` 清除。

## 适用边界
本轮没有修改 `merge/main.mjs`，因此普通模式的同步写入路径仍未迁移至 Web Locks；此修复只是为后续页面统一接入消除一类异步结果发布风险。禁止把 Node 模拟测试当作真实浏览器、iPhone Safari、微信 WebView、PostgreSQL 或 Edge 验收。应以本提交 SHA 对应的全仓库回归、静态安全与部署隔离、完整 Git 历史密钥扫描三项 CI 为准。
