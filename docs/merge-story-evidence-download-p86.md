# P86｜剧情异常存档下载请求的移动端可靠性与容量保护（未发布）

日期：2026-10-28；仅 Draft PR #59 剧情侧，包含普通经营 PR #58 的安全前向同步。

## 实际问题
P85 虽保全了异常 UTF-16 代码单元，但对白和工作台仍自行创建 Blob URL，固定 60 秒定时撤销。移动端 Safari/微信 WebView 可能冻结或提前触发定时器；大量重复点击也缺乏统一上限。孤立代理项扩展成 JSON 转义后，文件体积可能显著大于原始字符串。

## 本轮变更
- 安全合入上游 P2.65u 的有界下载请求器，剧情对白和工作台统一调用 `requestBrowserSaveDownload`，复用 2 MB 文件上限、最多 8 个待处理 URL、120 秒最小生命周期及过期清理。
- 保留 P85 的 `.txt` / `.utf16.json` 原文保全与文件名。下载被拒绝时区分“编码后过大”“待处理过多”和一般失败；明确原存档未修改，不允许把点击冒充落盘成功。
- 新增真实共享下载器故障注入：可逆 UTF-16 封装、点击后延迟撤销、体积超限在 URL 分配前拒绝、双模式存档不变；静态契约禁止剧情入口重新使用裸 Blob URL。

## 安全边界及待验收
没有改动经济、剧情、存档 schema、正式导航、main、部署白名单或线上数据库。此变更只是浏览器发起下载请求的可靠性保护；**真实 iPhone Safari / 微信 WebView 的下载落盘、文件可读性、后台恢复及 Windows 离线通关仍未完成**。localStorage 仍不是跨标签原子事务。PR #58/#59 必须保持 Draft；无用户另行许可不发布。
