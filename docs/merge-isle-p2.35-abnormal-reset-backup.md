# 《云屿百物铺》V3 · P2.35 异常存档重置前原始备份保护（未发布）

## 风险
普通模式在检测到存档损坏、保存结果不确定或跨标签冲突时，会暂停正常操作，但玩家仍可以显式确认重置。此前确认重置可以覆盖损坏的唯一原始存档，而未先核实有可保留的备份，可能丢失人工修复线索。

## 本轮变更
- 新增 `merge/reset-backup.mjs`，只为**异常状态下的确认重置**保留 `SAVE_KEY` 对应的精确原始 JavaScript 字符串。使用独立的 `*.abnormal-reset-backup-v3` 键，不读取或写入剧情模式键。
- 必须具备上一次可信读取的 `expectedRaw`，重置前重新检查原始存档、备份槽；若槽位已有不同内容则拒绝覆盖。只有写入后精确读回匹配，才允许继续调用现有 `persist(...,{confirmedReset:true})`。
- 原始存档可能已损坏，因此不能以 V3 校验成功作为备份前提；备份预算限制为 2,000,000 UTF-16 字符单位，过大或浏览器拒绝写入时中止重置。
- 正常存档的既有确认重置流程保持不变；异常状态下如果存档被另一标签修改、备份冲突、空间不足或读回不一致，保留原始内容并提示先导出核对。
- 同源浏览器备份并非独立持久化文件，浏览器清理数据时仍可能一起丢失。建议玩家先核实外部下载文件再重置。

## 专项测试与边界
`tests/merge-reset-backup.test.mjs` 覆盖损坏字符串的精确保留、重复备份幂等、备份槽冲突、跨标签基线变化、存储写入失败/静默丢弃/写后竞争及 UI 先备份后重置的接线顺序。

同步 localStorage 的多次读写**不是原子事务**。即使有读回校验，未接入 Web Locks 的旧标签仍可能在最终检查后竞争写入；本轮不声称彻底解决多标签原子性，也不声称已完成真实 iPhone Safari、微信 WebView、真实数据库或 Edge 验收。
