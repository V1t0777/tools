# 《云屿百物铺》V3.1 · P2.64e 迟到跨标签事件与旧交互防重放

**范围：普通模式独立 Draft 分支的持锁候选页面 `merge/main-locked.mjs`。本轮不切换 `merge/index.html`，不发布。**

## 发现的问题与根因

在实际候选页面接线审查中，发现一个既有 DOM 测试没有覆盖的竞态：另一标签已经更新 localStorage，但本标签的 `storage` 事件尚未送达。原有 `revalidateResumedSave()` 可以正确调用 `runtime.reconcile()` 采用经过验证的较新进度，却没有通知发起操作的调用者「本次操作来自旧 DOM/棋盘」。因此同一条点击、仓库操作或拖拽释放可能继续使用旧槽位/旧目标，在新进度上执行一次有效但不符合用户原意的操作。这不是锁实现错误，而是**读取新进度后旧交互重放**。

## 本轮同主题改动

1. **统一只读预检返回值**：`revalidateResumedSave()` 现在仅在当前存档与运行时可信基线完全一致时返回 `true`。发现新版本并成功采纳时，先清除旧拖拽、旧选择及整理提示，再要求用户在新棋盘重新操作；发现异常仍按既有安全阻断处理。
2. **四类操作入口共同执行该门禁**：玩家动作提交 `commit()`、点击或键盘激活 `touchCell()`、`pointerdown` 捕获、`pointerup` 投放以及可写计时器都检查预检结果。只有预检未发现更新的当前事件才可进入后续操作。此举不会禁止用户随后在新棋盘上发起真正的新动作。
3. **补齐 DOM 组合回归**：新增四项测试，分别模拟迟到 `storage` 的生产器点击、已选原料入库、移动端拖拽落点以及键盘激活。测试使用现有 Node DOM/Storage/Web Locks 注入环境执行真实候选页面代码，验证旧事件不写盘、新事件可继续、剧情存档保持不变。

## 安全与性能边界

- 不更改存档结构、经济数值、锁名称、云端服务、正式导航或部署白名单。
- `reconcile()` 仍只读，不向其他标签回写；新版本合法时可以采纳，但不能将旧交互自动转换为新版本的操作。
- 检测到损坏或不安全分叉时仍暂停写入，保留原始数据导出能力。
- 事件入口多一次只读比较，与既有的精确原始存档校验同级；没有新增每秒全量渲染，合法新版本更新才重建视图。
- 本轮**没有**切换当前试玩入口；测试不代表真实 Safari、微信 WebView、Cloudflare Pages 或云存档验收。
