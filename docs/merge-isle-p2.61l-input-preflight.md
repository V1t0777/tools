# P2.61l · 普通模式点击与拖拽开始前的原始存档复核

## 问题
现有页面通过 storage、focus、visibilitychange 与 BFCache 恢复事件检查跨标签存档，但这些事件可能延迟或缺失。旧标签在未收到事件前仍可选择旧棋盘物品或捕获拖拽指针；最终同步保存虽有原始字节 CAS 防护，交互本身仍可能使用过期视图。

## 最小改动
- 普通模式 `touchCell()` 在允许点击、键盘选择或生产前，调用已有只读 `revalidateResumedSave()`。
- 主按钮 `pointerdown` 在指针捕获和清除旧点击抑制标志前，同样核对原始存档。
- 存档已变更、移除、损坏或不可读取时，沿用已有阻断状态，清理旧拖拽、选中与提示；**不写回、不合并、不自动恢复**。
- 既有已阻断页面不因新的检查而解除阻断；非主按钮不新增存档读取。
- 正常存档保留点击、键盘和拖拽行为。额外的本地读取可能增加移动端每次手势的开销，后续需实机评估。

## 验证
新增 `tests/merge-input-preflight.test.mjs`，直接抽取真实页面处理器，验证延迟 storage 事件前的版本变化、原始存档缺失/损坏、正常点击与指针捕获，以及只读不写。旧版 VM 测试补足新增只读函数桩，不放宽已有业务断言。

## 未解决的风险
这是交互入口的尽力而为复核，**不是原子事务**。其他标签仍可在最后一次读取后写入，现有同步 `persist()` 也尚未迁移到统一 Web Locks；启动、动作、计时器与重置必须在同一协调边界下整体迁移。真实 iPhone Safari、微信 WebView、多标签端到端及云端 PostgreSQL/Edge 均未验收。
