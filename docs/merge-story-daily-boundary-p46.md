# 《云屿百物铺》P46 · 跨午夜动态事件安全刷新（开发分支，未发布）

## 问题
此前“今日事件”只在其他 UI 操作引发 `render()` 时重新计算本地日期。玩家长时间停留页面（尤其 iPhone 浏览器后台恢复）时，可能看到昨日事件；更严重的是，午夜前打开的事件对白可在午夜后继续提交，形成跨日误读。此问题不涉及普通模式资源，但影响叙事时序与用户信任。

## 本轮行为
- 新增纯函数 `canCommitDailyIncident`：只有**打开当日**与**提交当日**一致，且同一剧情包里当前 `dailyStoryIncident` 仍然选中**同一个条目对象**时，才允许事件提交。非法日期、异常进度、DLC 同名对象均拒绝；主线/支线不受日期约束。
- `ui.mjs` 在打开事件、点击确认和获得故事 Web Lock 后的提交校验中复核事件归属。跨午夜的旧事件对白被关闭并刷新；如等待锁期间日期变化，现有写入失败保护会保守阻断旧页，须重新打开核对。
- 可见页面每 30 秒检查本地日界；`pageshow` 和 `visibilitychange` 恢复路径继续即时重绘。计时器**只读**，不自动保存、领取奖励或改变随机种子。
- 新增五项测试覆盖跨日拒绝、同名 DLC 隔离、异常日期/进度、主支线兼容和 UI 结构安全。

## 验证与边界
专项 `node --test tests/merge-story-daily-boundary-p46.test.mjs`；全仓库 Node、`bash scripts/security-check.sh`、完整 Git 历史密钥扫描，以该提交 SHA 的 CI 为准。

**未解决：** 同一天推进主线会改变可用事件候选集合，`dailyStoryIncident` 可能改选另一事件；本轮只处理午夜过期的旧事件，**不宣称解决同日候选集合稳定性**。浏览器系统时间被人为调整、后台计时器节流、iPhone Safari/微信 WebView 的真实焦点与事件关闭表现需真机验证。未新增存档字段、数据库或奖励逻辑。
