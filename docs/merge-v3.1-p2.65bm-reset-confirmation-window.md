# P2.65bm｜重置确认后锁等待与备份写入窗口的竞态门禁（2026-10-29）

## P0 目标与边界

普通经营模式确认重置后，仍可能在获取 Web Lock 之前发生 pagehide/BFCache、其他标签改写；要求备份的重置还可能在原始备份槽写入时失去页面许可，或遭遇未遵循 Web Lock 的旧标签写入。任何情形都不能把旧确认当作新授权、覆盖新进度或声称重置成功。

## 本轮新增确定性测试

`tests/merge-normal-reset-confirmation-window.test.mjs` 使用真实 `createNormalPageRuntime.reset` → `commitNormalResetWithLock` → 原始备份/存档事务链；仅将 Web Lock 的授予时机和 localStorage 事件注入为可控替身。四个独立场景：

1. 已确认重置、锁尚未授予时页面失效：拒绝重置，不创建备份，不写普通存档。
2. 已确认重置、锁尚未授予时其他标签更改原始字节：拒绝旧基线，保留新字节，不创建备份。
3. 写入并核对原始备份期间页面失效：保留原始普通存档，允许已经写入的原始备份继续存在，不再执行重置。
4. 备份写入期间旧标签更改普通存档：拒绝重置，保留更新后的普通存档与原始备份。

所有场景都要求剧情存档及独立的恢复前备份保持原样。测试不伪造成功收据，不放宽写锁、安全阻断或经济规则。若已成功写入安全备份但重置失败，保留备份而非删除，是明确的故障安全结果。
