# P2.65bi｜普通经营模式已加载页面的断网闭环（2026-10-29）

## 发行目的
首发是**不依赖云服务的离线单机 Web**，并不等于已实现 PWA 离线首次加载、断网重新打开或离线安装。此前已覆盖本地存档、真实下载、Web Locks 与移动视口，但缺少浏览器明确处于 offline 状态时的连续经营和导出证据。

## 本轮专项门禁
在真实 Chromium 中加载普通经营页面并完成既有双标签/BFCache/移动触控回归后，使用 CDP `Network.emulateNetworkConditions` 设置 offline，且检查 `navigator.onLine === false`：

1. 通过现有生产器完成一次正常经营写入；存档 revision 恰好 +1、体力恰好 -1，不允许重复提交。
2. 仍在断网状态下点击现有本地存档导出按钮；等待浏览器真实生成新的 JSON/TXT 文件，解析后逐字段等于本轮已验证的 localStorage 快照。
3. 导出操作不得改变存档；恢复网络模拟后检查浏览器回到在线状态。

测试不替换 Web Locks、localStorage、真实经营引擎或 Blob 下载；不连接 Supabase、不修改经济与云端逻辑。失败必须使浏览器回归失败，不能通过模拟文件落盘或仅检查“已请求下载”冒充成功。

## 验证边界与剩余风险
- CI 结果以**新提交 SHA**的全仓库 Node、`security-check.sh` / 静态部署隔离、完整历史密钥扫描三项为准；不能引用旧 SHA 绿灯。
- Chrome 的断网模拟只证明**已加载页面**仍能经营与下载；不证明 Safari/微信 WebView 的文件落盘、系统分享菜单、后台挂起后的恢复，也不证明断网重载。
- 后续真机需核对：iPhone Safari 与微信内置浏览器分别在页面加载后关闭网络、完成一次经营操作、导出 JSON 并从“文件”或下载管理器实际打开，重新联网后进度无回退。
- 继续保持 PR #58/#59 Open/Draft，不合并 main、不发布、不触碰生产 Supabase 或部署配置。
