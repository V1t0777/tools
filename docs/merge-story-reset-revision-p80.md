# 《云屿百物铺》剧情 P80｜重置修订号单调性与上游安全同步（未发布）

## 修复范围
- 剧情对白存档底层写入器 `writeStorySave` 的 `confirmedReset` 路径：原实现对有效旧存档跳过修订号比较，允许在持有准确原始快照时直接写回相同或更低 revision；这可能破坏重置后的 ABA 防护。现要求**有效旧存档必须严格递增 revision**，与剧情工作台及上层对白重置门禁一致。
- 对损坏原始对白记录仍保留用户明确确认后的重置通道；普通经营、剧情工作台存档键均不读取或修改。
- 安全汇合普通经营 PR #58 的 P2.65o 原生文件读取 45 秒超时保护，保持原代码及测试；不更改其导入/恢复逻辑。

## 专项验证
- 有效存档：重置到更低/相同 revision 必须拒绝且不写入；更高 revision 可以写入。
- 损坏存档：明确重置仍可写入；正常经营和剧情工作台原始内容保持不变。
- 并发旧标签：精确原始字节不一致时，直接写入和共享锁入口均拒绝覆盖。
- GitHub Actions 必须在本轮新 SHA 上验证 Node 全仓库回归、静态安全与部署隔离、完整 Git 历史密钥扫描。CI 不是 Safari/微信真机验收。

## 风险与边界
- `localStorage` 的检查再写入仍不是跨标签原子事务；Web Locks 只协调参与协议的标签。
- 真实 iPhone Safari / 微信 WebView 的后台恢复、文件读取/下载落盘、多标签与 Windows 手工验收尚未完成。
- PR #58/#59 保持 Draft；不合并 main、不发布 Pages/Cloudflare/Edge、不改正式入口/白名单、不触碰生产 Supabase。
