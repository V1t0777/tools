# 云屿 V3.1 · P2.65q｜锁等待期间的存档恢复授权失效保护

## 本轮真实发行阻塞

普通模式页面在完成文件预检与二次确认后调用 `runtime.restore()`，但浏览器 Web Locks 请求可以异步等待。原实现只在发起恢复之前检查页面生命周期；若等待锁期间发生 pagehide/BFCache 或导入取消，旧事务可能在后来获得锁时仍然保留备份并写入存档。UI flight 会阻止发布过期结果，但无法撤销已经完成的写入。

## 改动与安全契约

1. `coordinateNormalSaveRestore` 接收可选同步 `canCommit` 守卫，且只在确认获得正确独占锁之后、任何备份/存档写入之前执行。守卫返回非 `true` 或抛错时，返回明确的 `RESTORE_CANCELLED_BEFORE_WRITE`，不写入任何键；旧调用仍默认允许（兼容既有直接调用）。
2. 普通页面运行时将确认时的 epoch、页面状态、flight 阻断状态与导入 AbortSignal 绑定至该守卫。页面失效或文件读取权限取消后，即使迟到获得锁也不能恢复。
3. 导入流程向运行时传递现有 AbortSignal；确认和锁等待共享同一授权。已确认没有写入的取消属于可重试拒绝，不应把正常经营永久锁死。
4. 增加锁适配器与页面运行时的专项 Node 回归：迟到锁授权、守卫抛错、BFCache 失效、取消后重试、恢复前备份槽及剧情存档隔离。

## 风险与验证边界

- 守卫只能阻止 **写入前** 的过期事务。锁内同步备份与写入一旦开始，后续页面事件无法原子撤销；出现不确定回执仍必须停止操作并重新核验。
- Web Locks 仅协调遵循同名锁的标签页，不替代精确 localStorage 原始字节检查。
- Node/DOM 模拟不等于真实 iPhone Safari、微信 WebView、双标签浏览器或文件下载落盘验收。
- 本轮仅修改 Draft PR #58 的普通模式代码与测试；不修改剧情源文件、main、部署白名单、Supabase 或任何发布设置。
