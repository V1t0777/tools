# 《云屿百物铺》V3 · P2.61b Web Locks 重复/迟到回调阻断（未发布）

## 问题与范围

普通模式尚未完成实际页面异步 Web Locks 全路径接线；P2.45 的 `withNormalSaveLock()` 已被未上线的动作、计时器、启动和重置事务复用。此前仅用 `callbackSeen` 判断回调是否出现，若非规范锁提供者重复调用回调，可能执行第二次写入；若请求先结算、回调后到达，也可能在调用方已收到失败结果后执行迟到写入。

真实浏览器的规范 Web Locks 实现通常不会这样调用回调，但未来页面接入需要对异常提供者保持失败关闭。本轮仅加固此公共边界，不声称浏览器 Web Locks 本身存在此缺陷。

## 单一工程增量

`merge/normal-save-lock.mjs` 记录回调是否已经调用、是否重复、锁请求是否已结算。重复或迟到回调均拒绝执行事务；在请求结算前发现重复回调，即使提供者返回第一次成功结果，整体也报告 `SAVE_LOCK_OUTCOME_UNCERTAIN`，不宣称安全成功。原有锁名、独占/非排队语义、真实一次回调及异常处理保持不变。

`tests/merge-normal-save-lock.test.mjs` 新增三组专项回归：顺序重复回调且伪造第一次成功、首个事务未结束时并发重复、请求已成功或异常结束后的迟到回调。测试使用模拟锁提供者，**不是 iPhone Safari、微信 WebView 或真实跨标签验收**。

## 限制与下一轮

本修复不能撤销已经执行的第一次事务；若锁提供者在首次异步事务进行中提前拒绝，仍可能存在结果未知状态，必须由调用方冻结并重新核对存档。当前 `merge/main.mjs` 的同步 `persist()` 仍未使用统一锁，跨标签原子写入风险尚未解决。下一轮应先审查全部页面写入路径，再进行同批切换，避免新旧无锁/有锁写入混用。
