# P17 · 剧情存档跨标签竞态的第二次写前核对

## 可复现风险
现有剧情对白与经营工作台采用 `getItem` 比较原始快照，再序列化和 `setItem` 写入。两个标签页可能在第一次读取之后、序列化期间先后写入，导致后写者覆盖先写者；即使两次 `setItem` 都成功，最后一次覆盖仍可能丢失进度。

## 本轮可验证修复
两个故事专用 writer 均在序列化完成、真正写入之前，再读取**相同的专用存档键**并比较调用者的 `expectedRaw`。如有差异，直接拒绝写入；存储不可用/读取异常同样拒绝。首次保存、用户明确确认的重置也必须经过这次核对。没有新增存档键，没有改动普通模式存储、经济、生产器或剧情内容，也不读取/上传生产数据。

专项 `tests/merge-story-write-race-p17.test.mjs` 使用可重复的脚本化竞态：第二次读取时由另一标签更新同一键，验证两个 writer 均不覆盖竞争者记录；覆盖首次写入、确认重置、读取异常和无冲突成功路径。它不是双浏览器真机测试。

## 明确保留的风险
第二次读取与 `setItem` 之间仍然存在不可消除的非原子窗口；ABA（其他标签写入后又恢复完全相同原文）、浏览器崩溃、配额耗尽、iPhone Safari/微信 WebView 的 Web Storage 行为均不由此修复。不能将本轮描述为跨标签原子事务或已解决所有竞态。Web Locks 支持度和不支持环境的安全降级策略需要下一轮单独评估，不能未经验证直接上线。

发行边界不变：PR #59 保持 Draft；不合并 main、不发布、不触碰部署白名单/线上 Supabase、不制作后门。正式候选版必须先完成 iPhone 真机与内容质量验收。
