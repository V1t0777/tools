# 云屿 V3.1 · P2.65ab 普通存档导入显式取消与旧文件事件隔离（2026-10-28）

## P0 发行阻塞
部分 iPhone Safari / 微信 WebView 原生文件选择器可能既不触发 cancel，也不可靠触发 blur、focus 或 visibilitychange。原有 15 秒返回宽限机制在这种情况下无法启动，导致导入按钮一直提示“文件选择尚未结束”。不得通过自动覆盖存档或放宽恢复锁解决。

## 变更
- 在普通存档导入按钮旁提供仅在文件选择或读取待决时出现的“取消导入等待”按钮；沿用 save-actions 的 44px 最小触控区域。手动取消不读取、解析、重置或写入存档。
- 取消时撤销当前文件读取/锁等待的 AbortSignal；如果控制器不能可靠置位 aborted，保守阻断运行时而不是假装安全取消。
- 手动取消后创建新的原生 file input，并忽略已脱离 DOM 的旧 input 的迟到 change/cancel 事件，避免旧选择器冒充新一轮明确授权。原生 cancel 仍复用相同安全取消路径。
- 保留原有 15 秒宽限、Web Locks 锁内复核、恢复前备份槽保护、BFCache 保护、普通/剧情存档隔离。未修改 main、导航、部署名单或云服务。

## 验证
- 新增真实普通模式页面入口 DOM 回归三项：无任何浏览器返回事件时可手动取消并重新导入、旧 input 迟到事件不能授权新导入、挂起 File.text() 可取消、已确认但等待 Web Lock 的恢复可取消且不写入。
- 最新 HEAD 的全仓库 Node、security-check.sh / 部署隔离、完整 Git 历史密钥扫描均须分别核对 GitHub Actions，未完成前不得标记通过。
- CI 不能代替 iPhone Safari / 微信 WebView 原生选择器、双标签或文件下载落盘实测。

## 风险
- 原生选择器仍占据屏幕时，用户必须先返回页面才能点击取消按钮；这是显式恢复入口，不声称能强制关闭系统选择器。
- 旧浏览器若不支持可靠 AbortController，导入仍按既有策略拒绝或安全阻断。
- 后续须在真机确认按钮显示、44px 触控、选择器返回、文件重选及 WebView 行为；11/10 前未验证不得宣称 RC。
