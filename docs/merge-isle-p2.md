# 云屿百物铺 P2 经营成长：实现说明（研发分支，仅本地试玩）

> 非正式发行；不合并 main、不调整 GitHub Pages / Cloudflare 白名单、不创建 Supabase 表。
> 本窗口暂不生产游戏美术资产；占位 Emoji、现有 CSS 场景保持不变。

## 模块责任

- `merge/economy.mjs`: 版本化经济常量、等级门槛、可达订单级别、产出分布、仓库及建筑成本。
- `merge/engine.mjs`: 纯函数规则核心（合成、生产、交付、仓库、生产器升级、建筑建设）。
- `merge/legacy-engine.mjs`: 只用于校验 P1（schemaVersion=1）的旧存档，不用于新规则运行。
- `merge/storage.mjs`: 旧档升级并尝试保留一次备份。`schemaVersion=2` 为 P2 本地试玩状态版本。
- `merge/main.mjs`: 浏览器操作与渲染；仍无后台或网络调用。
- `tests/merge-economy.test.mjs`: 经济边界、可达订单、仓库身份、升级门槛、保底、迁移、长随机测试。

## 初始数值（需基于真实玩家样本复测）

| 项目 | P2 初始值 |
| --- | --- |
| 等级经验门槛 | 0, 28, 90, 190, 350, 590, 920, 1400 |
| 订单最高阶解锁 | Lv1:2; Lv2:3; Lv4:4; Lv5:5; Lv7:6 |
| 产出概率（Lv1 工坊） | 75% 一阶 / 22% 二阶 / 3% 三阶 |
| 产出概率（Lv2 工坊） | 60% / 32% / 8% |
| 产出概率（Lv3 工坊） | 50% / 36% / 14% |
| 保底 | 连续 9 次仅一阶，下一次至少二阶；每个生产器独立计数 |
| 生产器升级 | Lv1→2: 玩家 Lv2 + 70 金币；Lv2→3: 玩家 Lv4 + 180 金币 |
| 仓库 | 初始 4 格；Lv2 + 50 金币解锁 6 格；Lv4 + 140 金币解锁 8 格 |
| 建筑 | 门面 Lv2/60 金币；后院 Lv4/160；港湾 Lv6/330 |
| 建筑效果 | 门面完成后生成的新订单金币系数提高；旧订单收益不追溯改变 |
| 订单生成 | 3 个委托；按轮次三条可用生产器轮换，强制 tier <= 已解锁最高阶 |
| 奖励计算 | 使用低阶叶子等价期望值的**启发式估算**（不是实际平均消耗报告） |

仓库只收纳原料，不能存入生产器；仓库物品需要先取回棋盘才能交付订单。

## 关键边界

- P2 的本地余额、产出概率和建造状态仅为研发模拟；浏览器自行修改的 localStorage 不能作为未来 P3 权威经济账本。
- P1 → P2 迁移保留棋盘实例 ID、金币、经验、体力与订单（超过新等级限制的订单重新生成）；老数据写入 `toolbox.merge-isle.local.v1.backup-v1`，升级后的试玩存档仍保留原存储键，增加 schemaVersion 字段。
- P2 的订单体力估算用于相对比较：未使用库存、棋盘空间或实际历史产出模拟，**不可宣称已完成正式数值平衡**。
- 正式内容开发前须先补跨设备并发/幂等结算、安全策略、经济蒙特卡洛仿真、UI 移动实机与长时内存检测。
