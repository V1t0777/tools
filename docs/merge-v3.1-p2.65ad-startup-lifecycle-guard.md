# 云屿 V3.1 P2.65ad｜启动锁等待与页面离开写入保护（未发布）

## 发行阻塞与原因
普通经营模式的启动会在同一 Web Lock 内创建 V3 存档、迁移旧存档或推进体力。此前页面在等待锁期间进入后台或 BFCache，运行时虽暂停了 UI，但排队的启动回调仍可能执行存档写入。初始即隐藏的页面也缺少启动许可校验。此类写入不能以“未展示 UI”视为安全。

## 本轮修复
1. 启动运行时将当前生命周期代次与页面可见性绑定为可撤销许可。锁获取后才检查许可；页面离开或同步重入导致许可失效，拒绝启动写入。
2. 启动事务的所有存档写入（包括旧版迁移备份）通过许可守卫；同步存储回调触发页面离开后，不继续创建、迁移或推进存档。
3. 启动前后和最终读回后均检查许可。拒绝时不发布新状态，不将存档结果视为已完成；可能已经执行的同步写入不能撤销，必须按不确定结果阻断。

## 专项回归
- 失效许可下的锁回调零写入。
- 存储读取同步触发页面离开，禁止后续写入。
- Web Lock 等待期间 pagehide，禁止创建/发布普通存档。
- 首次存档读取期间同步 pagehide，阻断启动再生。

## 风险与验收边界
- Web Locks 仅保护协作标签，不能让 localStorage 本身具备跨进程事务能力。
- 旧版迁移过程中若浏览器在已完成同步写入之后突然离开，已写入数据不能回滚；只能保留原始备份并在重开时复核。
- 需继续验证真实双标签、BFCache、iPhone Safari、微信 WebView 与文件落盘。CI 不是实机结果。
- 不修改剧情源文件、main、正式导航、部署白名单、Supabase 或云存档服务端；PR #58/#59 继续 Draft，禁止发布。
