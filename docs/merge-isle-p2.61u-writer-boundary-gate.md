# P2.61u 普通模式统一写入事务迁移门禁（未发布）

## 背景与范围
P2.61l–t 已加强实际页面的原始存档复核、动作延迟求值、版本与输入纯度校验，但当前 `merge/main.mjs` 仍是同步 CAS：启动迁移、玩家动作、计时器、重置均未统一持有 Web Lock。已有 P2.45–49 的锁事务模块仍未接入实际页面。只把其中一条写入路径改为持锁，不能解决跨标签覆盖，反而可能制造“部分持锁、部分无锁”的虚假安全感。

## 本轮增量
新增 `tests/merge-normal-writer-boundary.test.mjs`，作为未来迁移的结构性门禁：
- 核对启动、玩家动作、计时器、重置四个锁事务入口存在，且复用同一个 `withNormalSaveLock` 排他边界；
- 当实际页面尚未调用任一锁事务入口时，确认其现有六处同步写入/计算标记仍可被审计，并禁止页面直接私自申请 Web Lock；
- 一旦页面开始调用任何一个锁事务入口，就要求四个入口同时接入，并移除现有直接启动、动作、计时器、重置写入路径，避免混合写入状态；
- 不改动生产代码、存档格式、经济数值、剧情或部署配置。

## 验证及局限
专项命令：`node --test tests/merge-normal-writer-boundary.test.mjs`。完整回归、静态安全与部署隔离、完整 Git 历史密钥扫描以**本次新 HEAD** 的 GitHub Actions 为准，未完成前不得宣称通过。

这是静态结构回归，**不是** Web Locks 真实浏览器并发测试，也不能证明所有运行时调用已原子化。未来全量迁移需要在同一受审查变更中更新此门禁、实现初始化异步门控与 UI 禁用、验证锁忙/不可用/丢失时拒绝写入，并安排真实双标签 iPhone Safari / 微信 WebView 验收。
