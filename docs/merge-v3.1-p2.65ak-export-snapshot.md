# V3.1 P2.65ak｜普通存档导出与跨标签快照一致性（未发布）

## 发行阻塞与行为

- 普通模式导出原先仅检查页面是否可见。玩家动作、计时、启动、重置或恢复仍持有异步写入事务时，导出可能捕获尚未完成的旧快照，界面却提示“当前存档已请求下载”。
- 普通模式导出按钮此前没有在用户点击时主动复核最新存档。其他标签已经写入、但 `storage` 事件延迟时，旧棋盘可能直接请求下载另一个标签的进度，用户未审阅新状态。

本轮仅调整 `merge/main-locked.mjs` 普通模式页面导出入口：

1. 页面隐藏、BFCache 未恢复或 `runtime.busy` 时，不允许启动导出；下载前原始字节复核也重新检查 busy/页面状态。
2. 健康且已就绪的普通存档在导出前执行只读 `revalidateResumedSave()`；若采用了新快照，取消当前旧按钮动作，要求用户在新棋盘上再次点击。
3. 对已核验的正常 JSON 导出，再检查文件内容与已发布 UI 的 `runtime.raw` 一致；异常/损坏/已阻断的原始存档仍可主动导出取证，不要求先修复或重置。

## 专项回归

- `tests/merge-locked-page-dom.test.mjs`：真实页面入口 DOM 夹具，等待 Web Lock 的动作与导出并发时必须拒绝导出，不影响原动作和剧情存档。
- 同一夹具：其他标签替换存档而 `storage` 事件尚未送达时，第一次导出仅更新已核验棋盘，不发起下载，不写入任何存档。

## 边界与剩余风险

本轮没有修改经济数值、存档格式、剧情源文件、云同步、部署或线上数据。导出仍只是请求浏览器下载，不能证明 iPhone Safari/微信 WebView 文件已落盘。Web Locks 仅协调主动参与者，原始字节复核不能实现跨进程原子快照。真实双标签、BFCache、iPhone 文件操作与完整安全 CI 仍为发行门禁。保持 Draft PR #58/#59，禁止未经额外授权发布。
