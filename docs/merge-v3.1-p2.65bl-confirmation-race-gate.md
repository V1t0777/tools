# P2.65bl｜导入双重确认与跨标签/后台竞争专项门禁（2026-10-29）

## 本轮 P0 风险

普通经营模式导入 JSON 时，浏览器原生 `confirm()` 可能在用户确认期间触发页面离开、后台切换、存档跨标签更新或运行时进入忙碌状态。若仍沿用确认前的旧存档授权，可能错误覆盖新的经营进度。降级恢复有两次确认，必须分别守住该边界。

## 关联验证

新增 `tests/merge-normal-import-confirmation-race.test.mjs`，直接调用真实 `performNormalSaveImport` 预检与确认流程，注入五种确定性竞争：首次确认触发页面生命周期变化、首次确认触发另一标签改写、确认时运行时变忙、第二次降级确认触发页面离开、第二次降级确认触发另一标签改写。

每种场景均要求拒绝恢复，保持当前存档原始字节或保留其他标签的新字节，不触碰独立剧情存档及恢复前备份；不允许确认失效后自动重试。仅最后一步锁内 `runtime.restore` 使用计数替身，不能把本测试称为真实浏览器或跨标签 Web Locks 验收。既有 Chromium 组合回归另行覆盖真实页面和 Web Locks。

## 安全与发行边界

本轮不修改正式运行时、经济规则、剧情源文件、正式导航、部署白名单、Cloudflare 或 Supabase。PR #58/#59 继续 Open/Draft，所有提交保留 `[CF-Pages-Skip]`。必须在最终 HEAD 核对全仓库 Node、`bash scripts/security-check.sh`/部署隔离、完整历史密钥扫描及是否存在意外部署；未验证前不得宣称成功。

剩余 P0：iPhone Safari、微信 WebView 原生文件选择、真实下载落盘、后台/BFCache 和跨标签操作仍待物理设备验收。11 月 10 日仅依据证据推荐或拒绝候选版，不代表发布授权。
