# 《云屿百物铺》V3 · P2.23 异步存档单飞保护（未发布）

## 本轮实现

新增 `merge/save-write-flight.mjs`：`createNormalSaveFlight(storage,lockManager)` 返回每页面会话一个轻量适配器，公开 `pending` 与 `write(state,options)`。首次调用转交 P2.22 受 Web Locks 保护的普通模式保存；异步尚未结束时，第二次写入立即返回 `SAVE_IN_FLIGHT`，绝不把后来的状态静默排队、丢弃后仍显示保存成功或偷偷回退无锁写入。

`pending` 在成功、拒绝或异常后均释放；返回状态来自 P2.22，只有 `SAVE_VERIFIED` 才能让未来 UI 更新持久化基线。重置仍须由实际 UI 获得用户确认；适配器本身不获取同意。调用方必须保留未保存内存态、禁止在失败后自动重试、向玩家显示明确错误并重新核对最新存档。

## 专项回归

`tests/merge-save-write-flight.test.mjs` 覆盖延迟持锁时重叠写入、确认写入后下一次精确基线、旧标签基线失败、锁不可用、未确认重置、异常释放、剧情模式隔离与页面未接入。

## 剩余风险

本轮**未接入** `merge/main.mjs`。这只是未来异步 UI 接线的单飞安全边界；不能代替业务状态队列或真实用户反馈，也不能宣称正式游玩保存已经获得跨标签互斥。现有页面仍有同步 `persist()`、启动时迁移、后台体力定时保存等未参与锁的路径；旧标签页同样可能无锁写入。下一阶段应先设计可恢复的未保存状态与 UI 提示，再逐步接入，并开展真实双标签、iPhone Safari 与微信 WebView 验收。
