# 第一卷剧情体验预览：发行候选前置研发记录

## 范围
独立的 `merge/story.html` 提供 **12 个主线场景、6 个支线、6 个每日事件模板**。这是可交互的**剧情垂直切片**，不是已完成的全量发行版本。玩家可在同一浏览器保存、恢复并回看内容。剧情记录的本地键与普通模式完全分离。

## 约束
- 不通过剧情接口发放金币、经验、体力、道具或成就；不调用云端服务，不修改普通玩法状态。
- DLC 采用独立内容包 ID，核心运行时不固定章节或最终结局。缺失 DLC 的进度不删除（沿用现有 mode-boundaries 和 pack preflight）。
- 对不合法剧情内容、非法完成顺序及异常存档执行拒绝；异常原始字节不自动覆盖。
- 浏览器多标签在常规顺序操作时检测到原文字节变化后拒绝旧页面覆盖；localStorage 不提供跨标签强原子写入保证。云存档尚未接入。
- 动态事件为按**本地日历日**确定的轻量叙事，不包含可无限刷取的经济奖励，也不使用真实天气接口。

## 自动化验收
```sh
node --test tests/merge-story-runtime.test.mjs tests/merge-story-ui-contract.test.mjs
node --test tests/*.test.mjs
bash scripts/security-check.sh
```
以上为需要在 GitHub Actions 环境验证的命令，不能把单元测试等同于真机验收。

## 仍然缺少的发行条件
1. 剧情任务与 7×8 合成棋盘、真实订单及建筑节点的接入；目前为独立可读可选择的剧情体验。
2. 第一卷正式美术、声音和逐幕文本审校；内容目前仍是功能性剧本。
3. iOS Safari、微信 WebView、Windows 全流程设备验收与弱网络、低空间及多标签故障验证。
4. 完整 P2/P3 上游分支集成和全仓库安全 CI 完成；当前所有内容仅在独立开发分支和 Draft PR 中。
5. 明确用户批准前，不合并 main、不修改正式导航或构建白名单，不上线 Pages/Cloudflare/Edge，不运行 Supabase SQL。

## 人工验收重点
打开普通预览中的「剧情体验」链接→首次保存→从第一章顺序阅读→选择分支→刷新恢复→解锁支线→切换每日事件→回看旧故事→双标签冲突提示→确认重置仅清空剧情进度而不改变普通经营。
