# P2.65bp｜真实 Chromium 双标签重置锁竞争与重新确认（未发布）

北京时间 2026-10-29 23 时轮次。目标仅是普通经营模式的 P0 存档可靠性，不改变引擎、数值、页面部署或剧情源文件。

## 本轮真实浏览器回归

在既有 `tests/merge-browser-real.test.mjs` 的双标签 Chromium / 原生 Web Locks / 本地存档场景末尾，新增如下可执行闭环：

1. 两个标签均采纳最新普通模式存档，确认 revision > 0；记录普通存档、恢复前备份及独立剧情存档原始字节。
2. 标签 A 持有与生产、计时、重置相同的 Web Lock；标签 B 经原生页面按钮和明确的 `window.confirm` 确认重置，必须收到可见的“占用存档”安全反馈。普通存档、恢复前备份、剧情存档保持逐字节一致。
3. 释放锁后，不允许旧确认自动重放；标签 B 必须再次主动点击、再次确认，才能写入 revision=0 的新普通存档。旧恢复备份和剧情存档不得改变。
4. 标签 A 收到另一个标签的低版本重置后必须进入暂停状态；其旧生产按钮不能复活重置前进度。

测试使用真实 Chromium 两个标签、真实页面按钮、同源 localStorage 和浏览器 Web Locks；仅确认对话由测试控制，未模拟锁或存档运行时。测试失败必须使 CI 失败，不能将自动重试或旧 SHA 的绿灯冒充本轮结果。
