# 云屿百物铺 P3.6 — 本地存档写入基线与故障注入（仅开发分支）

**严格禁止发布：** 仅修改 `merge/storage.mjs`、`merge/main.mjs`、本地安全测试及本文件。不得合并 main、改正式工具箱导航/部署白名单、部署 GitHub Pages/Cloudflare/Edge、执行 Supabase SQL 或推进美术。

## 问题

P3.5 能拒绝低 revision 覆盖高 revision，却仍允许**相同 revision、不同内容**的两个浏览器标签页相互覆盖。例如能量恢复改变 `energyAt` 但不增加 revision；或一个标签在另一个标签明确重置后，仍用更高 revision 的旧存档覆盖新存档。两个标签先后写入时，这类覆盖不一定触发 P3.5 的回退保护。

## 本轮改动

1. `loadLocal()` 在成功读取合法 P2 存档时额外返回原始 `raw` 字符串；首次无存档返回 `raw:null`。成功迁移旧存档后返回实际写入的新版序列化字符串。
2. `saveLocal(...,{expectedRaw})` 在非显式重置时先检查 `getItem(SAVE_KEY)` 是否与该标签最后读取/成功写入的字节**完全一致**；不一致时返回 `false`，不写入。旧调用者未传入 `expectedRaw` 时维持兼容行为；正式 P2 试玩页面始终传入该参数。
3. 页面在每次成功保存后更新 `persistedRaw`，在 `storage` 事件中识别**同 revision 但内容不同**的其他标签页更新，并在当前没有未保存错误时重新载入；若当前已有未保存问题，则不自动丢弃内存进度。
4. 明确重置仍须用户确认；重置存储失败时不再错误提示“已重置试玩进度”。

## 故障注入与回归

新增 8 项测试：同 revision 两标签分歧、重置后旧标签回写、首次空存档竞争、连续成功保存更新基线、原始 JSON 格式保留、旧版迁移后基线、显式重置豁免和基线不匹配时零写入。测试使用内存存储桩，不需要访问线上数据。

复现：

```sh
node --test tests/merge-*.test.mjs
bash scripts/security-check.sh
```

## 明确的安全边界和剩余风险

- 这是**尽力而为的顺序冲突检测**，不是事务。`getItem` 与 `setItem` 之间仍可能发生完全同时写入，无法凭 localStorage 消除 TOCTOU 竞态。未来正式云存档必须依赖服务器事务 CAS、幂等编号与用户确认的冲突恢复。
- 没有 Web Locks 的浏览器不具备可靠的跨标签写入互斥；本地试玩目前仍不强制 Web Locks，以免破坏旧浏览器的离线试玩体验。发现不匹配时拒绝保存并持续警告。
- 本轮未修改正式云指令队列，也未把本地试玩货币或物品同步至线上；本地存档仍可被手动篡改。
- 真实 iOS Safari、微信内置浏览器、断电/进程终止及同时写入的实机端到端验证仍待完成。
- 若一个标签已出现未保存的进度，自动接纳另一个标签的更新可能导致丢失本地内存进度；因此本轮只在没有保存错误时自动接纳，其他情况需要用户自行处理。
