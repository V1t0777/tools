# 《云屿百物铺》V3 · P2.36 异常重置前备份独立导出（未发布）

## 风险与目标
P2.35 在普通模式异常重置前保留了浏览器内部的原始备份，但重置后「导出原始存档」只能导出新的活动存档。用户无法从界面取得那份旧备份，清理浏览器数据可能让人工恢复线索一起丢失。

## 本轮单一工程增量
- 在普通模式的本地存档区域新增「导出重置前备份」按钮，与现有导出及重置并列；窄屏复用自动换行与 44px 触控高度。
- 将备份键常量集中到 `merge/storage.mjs`，保留 `reset-backup.mjs` 原导出兼容性，不改存储键名或旧数据。
- `prepareAbnormalResetBackupExport` 仅读取 `ABNORMAL_RESET_BACKUP_KEY`，复用 P2.33/P2.34 的 UTF-8 文件体积预算和孤立 UTF-16 代理项封装。没有备份时明确失败，不自动改为导出活动存档。
- 历史异常备份无论内容能否通过 V3 校验，均标记为人工核对的旧备份，不宣称可直接恢复。下载动作只创建本地 Blob 链接，不执行写入、上传、SQL、迁移或游戏操作。
- 专项回归覆盖旧备份与新活动存档隔离、剧情模式隔离、备份缺失、异常 UTF-16 无损封装、超限拒绝和 UI 只读接线。

## 安全边界
- **下载请求不等于文件已落盘**：iPhone Safari / 微信 WebView 必须由用户确认下载真实存在并核对内容；不声称实机验证。
- **备份不等于恢复**：不提供自动导入，异常文件不能直接当有效 V3 存档使用。
- 浏览器内部备份可能被清理数据或配额驱逐；建议导出后另行安全保管。
- 同步 localStorage 的多标签竞争仍未具备事务级 Web Locks 保护，下一轮继续评估。
- 本轮仅修改独立 Draft 分支；不修改 main、正式导航/部署白名单，不合并、不发布、不运行线上 Supabase SQL/迁移、不制作美术或作弊后门。

必须以本次 HEAD 对应全仓库回归、静态安全/部署隔离、完整 Git 历史密钥扫描三项 GitHub Actions 全部成功，才能标记 P2.36 工程验证完成。
