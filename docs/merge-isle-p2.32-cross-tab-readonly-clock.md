# 《云屿百物铺》V3 · P2.32 跨标签同步不提前展示未保存体力（未发布）

## 本轮问题
P2.25 起，普通模式的 storage 事件已禁止直接写回，但仍在接纳其他标签页的 V3 存档后立即执行 `advanceTime(fresh.state)`。这会在尚未经过 P2.26 的保存读回验证前，让本标签页展示新增体力或已完成的生产器冷却，与“先确认持久化，再接受进度”的约束不一致。

## 修复
- `merge/main.mjs`：跨标签事件只采用 `peekLocalV3` 验证通过的原始远端状态；不在事件回调里调用 `advanceTime`，保留 P2.29–P2.31 的同修订号经济/时钟冲突校验。
- 后续每秒计时器仍负责恢复体力/生产器冷却，并先执行 `persist(updated)`，验证成功才更新画面；保存失败则保留原状态并暂停操作。
- `tests/merge-storage-event-policy.test.mjs`：更新原有接线断言，并用 Node vm 执行实际 storage 事件回调，验证较高修订号与同修订号时间进展均不会额外计算未保存资源。

## 验证边界
Node vm 测试是代码路径级模拟，不等于真实浏览器双标签、iPhone Safari 或微信 WebView 实机验收。同步 localStorage 仍存在未被 Web Locks 覆盖的跨标签读写竞争；本轮只修复“事件接纳后提前展示未保存资源”，不声称实现原子事务或云存档。
