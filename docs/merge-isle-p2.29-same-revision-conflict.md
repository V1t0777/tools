# 《云屿百物铺》V3 · P2.29 同修订号跨标签冲突阻断（未发布）

## 问题与范围

P2.25 的只读 storage 监听会接受修订号相同但原始字节不同的远端 V3 存档。体力自然恢复不增加 revision，确实会造成这种差异；但同修订号也可能包含不符合时钟更新规则的金币、棋盘、订单或其他经济字段变化。无条件采用会悄悄替换当前画面。

## 本轮修复

- 新增 `merge/storage-event-policy.mjs`：只允许同修订号的**单调时钟进度**（体力与时间前进、生产器冷却结束后恢复）或完全相同的业务状态通过。其余业务字段发生变化、体力或时间倒退、生产器反向冷却，均拒绝静默同步。
- `merge/main.mjs`：原有较低修订号拒绝规则不变；新增同修订号策略检查，失败时保留当前内存状态与旧可信原始基线，设置 `CURRENT_SAVE_CHANGED`，提示先备份并重新打开核对。
- `tests/merge-storage-event-policy.test.mjs`：覆盖同修订号正常体力恢复、旧时间倒退、金币/棋盘/订单变化、生产器冷却单调性及 UI 只读接线。

## 边界与已知风险

这是**保守的只读冲突判断**，可能把非标准但实际合法的同修订号写入判为冲突；以不静默覆盖玩家经济进度为优先。它不是事务锁，不能保证在同步 localStorage 比较和写入之间没有跨标签竞态。尚未接入 P2.21–P2.24 的异步锁与单飞适配器，也未做双标签真实浏览器、iPhone Safari 或微信 WebView 实机验收。
