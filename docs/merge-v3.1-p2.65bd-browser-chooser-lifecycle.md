# P2.65bd · 普通经营模式文件选择与后台触控恢复门禁（2026-10-29）

## 目的与实际改动

本轮聚焦两个同属移动浏览器页面生命周期的发行风险，不修改游戏经济、存档格式或运行时。

1. 在真实 Chromium 页面打开普通模式导入文件选择器后，尝试点击“重置试玩进度”和“导出原始存档”。验证待选择文件期间不弹出破坏性重置确认、不下载可能过期的存档、不改变当前存档和恢复前备份的**原始字节**；取消选择后应解除等待。测试只替代原生系统选择器的弹出，仍执行页面按钮、localStorage 与运行时守卫。
2. 后台拖拽、另一标签写入、返回前台后的新生产器触控，不再依赖固定 140ms 睡眠推断命中区域已恢复，而是验证实际 elementFromPoint 命中生产器、页面可见且拖拽浮层已清空。恢复写入仍须严格为一次 revision 增量和一次体力消耗；超时保留失败，并记录既有脱敏状态快照。

## 验证边界与风险

本轮测试仍使用真实 Chromium 与 CDP 模拟触摸，**不是** iPhone Safari 或微信 WebView 的原生文件选择、下载落盘、物理触控测试。不能以单次通过宣称历史间歇超时根因彻底消除；应继续观察后续多轮 CI，若失败需核对失败快照与真实运行时竞态。320px 极窄屏棋盘操作、真实 iPhone/微信文件选择及下载、剧情首卷集成仍是候选版验收阻塞。

本轮任何新提交须核对其**最终 HEAD** 的全仓库 Node、`bash scripts/security-check.sh`/部署隔离、全历史密钥扫描和 Chromium 日志；未全部完成前不得宣称 CI 通过。PR #58/#59 保持 Open/Draft；禁止写/合并 main、发布 Pages/Cloudflare/Edge、改正式导航/部署白名单、线上 Supabase SQL/迁移或添加作弊后门。提交必须保留 `[CF-Pages-Skip]`。

## 首次 CI 失败与安全回退

提交 `e73fef4` 首次 Node 执行为 **1192/1193**：新增待选文件阻断重置/导出专项通过，但后台恢复后的新触控偶发未写入。失败快照表明 Chromium 已分发 `pointerdown → pointerup → click`，页面可见且存档未损坏；不能把失败仅归咎于触控命中区域。

曾尝试减少无变化倒计时的锁竞争，但提交 `e201c97` 的真实 CI 揭示 **4 项旧有安全契约或新增测试失败**：旧有静态门禁明确要求计时器仍由统一 Web Locks 协调，不允许页面自行调用引擎 `advanceTime`；新增恢复测试还存在初始状态预期错误。为避免降低既定安全边界，**本轮撤回这项计时器改动及相应新测试**，恢复 `merge/main-locked.mjs` 和 DOM 测试原始字节。仅保留独立的真实 Chromium 文件选择安全回归、后台命中区域检查与失败诊断。历史失败如实保留，不以旧 SHA 的通过记录替代当前门禁。

后续需要在不绕过计时器写锁的前提下定位偶发触控被拒绝的具体时序（包括运行时忙碌、页面重绘和触控许可失效）。不得通过放宽断言或无界重试掩盖；仍须完成 iPhone Safari、微信 WebView 和文件下载落盘真机验收。

## Chromium 启动门禁的独立失败

最终候选前一提交 `2220943` 的首次 Node 回归 **1192/1193**，失败发生在浏览器 DevTools 调试端口建立前（`TIMEOUT: Chrome debugging port`），并非游戏断言。原等待上限 12 秒，在全仓库并发测试负载下可能不足。本次仅将**真实浏览器**启动等待改为有界 20 秒，不跳过浏览器、不注入 DOM 替身、不放宽触控、Web Locks、BFCache 或存档断言。仍须观察是否再次超时；若浏览器进程实际退出，应进一步记录安全的退出状态。CI 的首次失败仍保留为稳定性风险。
