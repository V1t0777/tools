# V3.1 P2.65am｜普通模式文件导入与经营写入互斥（未发布）

## 问题与影响

普通模式已有 Web Locks 保护最终存档写入，但原生文件选择器和 File.text() 读取阶段不占用该锁。旧页面在这段时间仍允许玩家生产/合成、计时器更新体力以及点击确认重置。虽然恢复事务最终会核验原始字节并拒绝过期恢复，但玩家可能在准备导入时意外重置进度，或被自动计时改写基线导致合法导入被拒绝。此处属于同一页面的操作闭环缺陷，不应依赖最终冲突拒绝作为正常体验。

## 本轮改进

- 在普通模式入口增加只读的 `importPending()`，统一识别原生选择器等待、隐藏队列及文件读取/恢复等待。
- 经营写入入口在导入未结束时明确提示并拒绝操作；确认重置在弹窗前拒绝，避免重置覆盖用户尚未完成的文件选择。
- 每秒体力/冷却计时在导入期间暂停写入；取消或正常结束后恢复既有计时路径，下一次计时仍按真实时间计算，不更改经济公式。
- 保持原有 Web Locks、原始存档备份、读回校验、页面生命周期撤销、剧情存档隔离和导出取证能力。导入读取本身不写入任何存档。

## 可验证证据及边界

`tests/merge-locked-page-dom.test.mjs` 新增三个实际 HTML 入口 DOM 场景：原生选择器未返回时拒绝重置/经营；文件读取挂起时拒绝计时、重置、生产而允许后续确认恢复；用户取消后迟到文件不得写入，正常经营可重新开始。最终全仓库 Node、`scripts/security-check.sh`、部署隔离与完整历史扫描必须以本提交 SHA 对应 Actions 为准，不能借用旧提交的绿灯。

该测试仍是 Node DOM 夹具，不代表真实 iPhone Safari/微信 WebView 的文件选择、下载落盘、BFCache 和双标签验收。不同标签之间的 localStorage 读写不具有跨标签原子性；仍须真实浏览器测试。PR #58/#59 继续保持 Draft/Open；不修改 main、正式导航/白名单、云端服务或线上数据，不部署、不发布。
