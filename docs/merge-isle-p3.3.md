# 云屿百物铺 P3.3 — 30 日经济仿真基线（未发布）

> 只增加**离线研发模拟器、测试和报告脚本**，不改变实际 P2 玩法、经济参数、生产站点、Supabase 或美术素材。2026-10-19 研发数据，非真实玩家数据。

## 方法

- `merge/economy-simulator.mjs` 调用**真实 P2 规则函数** `createInitialState`、`advanceTime`、`produce`、`moveOrMerge`、`fulfillOrder` 和升级函数，不直接修改金币、经验或奖励。每个随机种子使用确定性 LCG；不调用 `Math.random`、真实时钟、浏览器 API 或数据库。
- 3 种活跃度：轻度每天 1×8 分钟、中度每天 2×12 分钟、重度每天 4×20 分钟；每次操作假定 2 秒，虚拟日内均匀分布会话。每次生产耗 1 点体力，使用 P2 的自然恢复和生产器充能规则。
- 3 种购买策略：`balanced` 优先生产器→门面→仓库→其他建筑；`expand-first` 优先仓库→生产器→门面；`save-coins` 不升级。模拟策略自动选择可交付订单、自动合成同链同阶材料，按订单缺口选生产器。每个场景 5 个固定随机种子，共 **45 条 30 日轨迹**。
- 每天检查真实 `validateSave`；全程核对 `余额 = 累计订单收入 - 累计升级支出`、动作总数、体力支出、棋盘容量和经验单调性。固定黄金样例锁定当前经济输出，任何变更需复核差异，**不表示这些数值是理想目标**。

| 中度 | expand-first | 1,400.2 | 69,012.0 | 2 | 11 |

## 重要发现（暂不直接调参）

1. **成长过快：** 模型内最高等级 Lv.8 在第 1–4 天到达，明显快于 30 天的观察窗口。即使每天仅玩 8 分钟且不升级，仍在第 4 天达到等级上限。应在未来单独设计更长的等级曲线或内容解锁，**不要直接在本次测试中改动线上或试玩经济参数**。
2. **金币缺少后期消耗：** `balanced` 购买全部 11 项升级后，30 天仍累积 3.3 万–14.5 万金币，说明固定升级成本不足以形成长期金币回收。未来应考虑可重复的金币消耗点、经营建设阶段及通胀边界。
3. **仓库收益尚未量化：** 当前策略不会主动执行 `storeItem/withdrawItem`，所以 `expand-first` 只是改变升级顺序，无法测量仓库扩容对真人棋盘压力的帮助。需要另做有限理性玩家、低频整理和收藏保留场景。
4. **估算体力并非实际成本：** `estimatedEnergy` 是单件启发式估算，而模拟器会复用库存、合成并直接消耗已有材料；订单平均体力不能简单视为订单标价的真实边际成本。需要事件归因模型后才能调奖励。
5. **理想化操作模型：** 玩家即时完成所有可交付订单、自动整理棋盘、完全不失误、忽略 UI 操作延迟，无法替代真实玩家留存、操作行为或移动设备性能测试。仅适合作为经济风险预警和回归基线。

node --test tests/merge-economy-simulation.test.mjs
node --test tests/merge-*.test.mjs
node scripts/merge-economy-sim.mjs > economy-report.json

`economy-report.json` 是可重建的本地输出，**不应包含个人数据、账号信息或任何生产凭据**。正式仓库的完整安全检查须以 GitHub Actions 为准。
