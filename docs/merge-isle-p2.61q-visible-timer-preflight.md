# P2.61q · 普通模式可见计时器存档预检（未发布）

## 背景与范围
普通模式实际页面的 1 秒计时器此前先执行 `advanceTime(state, now)`；在体力/冷却无变化时不会调用写入 CAS，因此如果跨标签 `storage` 事件迟到且页面始终可见，旧标签可以继续展示未核实的状态。即使有变化，原实现也会先计算过期状态，再由同步 CAS 尝试拒绝保存。

本轮仅调整 `merge/main.mjs` 的可见计时器：跳过隐藏页面；对未阻断页面先调用既有只读 `revalidateResumedSave()` 核验原始字节，发现替换、移除、损坏或读取失败则立即暂停，不调用 `advanceTime`、`persist` 或后续资源刷新；匹配时才执行原计时器逻辑。已阻断页面不反复读取。没有更改游戏经济、存档格式、部署配置或任何正式导航。

## 回归与性能边界
`tests/merge-visible-timer-preflight.test.mjs` 直接执行真实页面计时器与恢复检查片段，覆盖无变化跨标签替换、到期恢复前冲突、存档删除/损坏、正常无变化、正常恢复及隐藏/已阻断状态。测试用受控存储与模拟持久化；不能代替浏览器跨标签端到端验收。全仓库回归、静态安全与部署隔离、完整历史密钥扫描必须以最终提交 SHA 对应的 GitHub Actions 为准。

可见页面每秒多进行一次只读存档解析，可能增加移动设备 CPU/同步存储开销；后续需以真实 iPhone/微信 WebView 性能测量决定是否引入安全的节流策略，不得以节流牺牲写入前验证。

## 尚未解决
当前普通模式仍使用同步 CAS，启动迁移、计时器、重置与游戏动作尚未整体切换到统一 Web Locks 写入边界；旧版未协调标签仍可在最后一次检查之后写入。没有真实 iPhone Safari、微信 WebView、PostgreSQL/Edge 实测，不构成 RC 或发布许可。

PR #58 和关联研发 PR 必须保持 Open/Draft；不合并 main、不调整正式导航或部署白名单、不发布 Pages/Cloudflare/Edge、不运行线上 SQL/迁移、不制作美术或作弊后门。
