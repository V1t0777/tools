# 《云屿百物铺》P2.10 — 补给冷却卡选择与倒计时交互修复（仅研发预览）

## 问题与目标

P2.9 Windows 验收通过后，代码复查发现一个多工坊交互缺口：原界面只在游戏状态发生变化时完整渲染补给面板。因此用户若将冷却卡目标由**可生产的 A 工坊**切换到**正在冷却的 B 工坊**，卡片按钮仍可能保持灰色，直到下一次资源变化后才被更新；下拉项的「剩余 N 秒」文字也不会持续刷新。

P2.10 不修改经济、体力上限、冷却公式、金币价格、成就和存档 schema。只修复界面派生状态与刷新方式。

## 实际改动

- 增加纯函数 `merge/supply-controls.mjs#getSupplyControlSnapshot(state, requestedProducerId, now)`。返回选中工坊、是否正在冷却、剩余秒数和四种道具的可用状态；纯函数不扣道具、不写存档、不创建/上传玩家数据。
- `merge/main.mjs` 监听工坊下拉选择的 `change` 事件，**立即**刷新冷却卡按钮启用/禁用状态。
- 现有每秒资源时钟额外更新轻量级状态，**不**为此重建棋盘、背包条目或商店，也不写入存档。
- 生产器下拉选项仅在选项身份集合改变时重建；常规每秒更新仅比较必要文本，保持当前选择，减少焦点跳动。
- 独立的 `#supply-cooldown-status` 显示剩余时间，使用 `aria-describedby` 与选择器关联；`aria-live="off"` 避免辅助技术每秒朗读倒计时造成干扰。
- 单元及静态交互回归 8 项：选择不同工坊立即变化、剩余秒数到期、零库存、满体力、无效工坊回退、无状态副作用、时钟无效值及 DOM 事件调用链。

## Windows 复验建议

1. 在 `D:\GitHub\tools-merge-preview` 执行 `git pull --ff-only`，不覆盖任何现存本地未提交修改。
2. 保持本地静态预览服务运行：`python -m http.server 8765 --bind 127.0.0.1`；在 Windows 浏览器打开 `http://127.0.0.1:8765/merge/`。
3. 使**烘焙工坊**进入冷却，但让**茶饮工坊**仍有可用次数；确保背包有工坊加速卡或星辉重启卡。
4. 切换下拉选择：选茶饮工坊时冷却卡不可用，改选烘焙工坊时无需其他操作立即可用。观察剩余秒数逐秒下降；冷却自然结束后按钮应自动禁用。
5. 再测刷新页面后目标状态和库存正确恢复、模拟窄屏下控件无重叠。

## 验收与边界

Node/Actions 回归可验证纯逻辑及静态接线，但**不等于** iPhone Safari 真实焦点行为、微信 WebView 或跨设备云存档测试。此阶段不添加作弊后门或管理端口；PR #58 继续 Draft，不合并/修改 `main`，不发布 Pages/Cloudflare/Edge，不修改生产导航与部署白名单，不执行线上 Supabase SQL 或碰已有线上数据库，不制作美术素材。实际 CI 必须以提交后对应的全仓库测试、部署隔离检查、全历史密钥扫描全部通过为准。
