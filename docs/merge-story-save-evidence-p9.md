# P9：损坏的剧情经营存档只读保全（未发布）

## 目标
剧情工作台已对损坏存档与过期标签页写入采取阻断，但之前界面仅提供确认重置，玩家无法先将异常内容保留到独立文件以供人工排查。本轮增加主动操作的**本机文本证据导出**，不尝试自动恢复存档，也不触及普通模式存档、服务器或生产数据库。

## 流程与安全条件
- 仅在工作台加载结果为 `CORRUPT_SAVE` 且原始记录为字符串时启用按钮；导出前需浏览器原生确认。
- `captureStoryWorkshopEvidence` 读取指定剧情键，并与页面首次读取的 `expectedRaw` 精确比较。跨标签修改、删除、存储访问异常、无快照、未同意均拒绝；超过 2,000,000 个 JS 字符的记录拒绝导出，以避免在异常设备上构建超大 Blob。
- 本地 Blob 下载不调用 `fetch`、服务端 API 或外部上传；导出的是 `localStorage` 原始字符串内容，不进行 JSON 解析、自动修复或重写。
- 浏览器仅能确认已尝试触发下载，不能证明 iOS Safari / 微信 WebView 真的保存到“文件”。玩家必须自行确认文件存在且可打开。
- 确认重置损坏存档前增加单独风险提示，但仍保留原有 CAS 校验与显式用户确认；正常档的重置交互不改变。

## 测试与剩余风险
- `tests/merge-story-save-evidence.test.mjs`：用户同意、原始内容不变、与普通存档隔离、跨标签过期、删除、异常、过大拒绝、UI 安全契约。
- 仍需检查 iPhone Safari 与微信 WebView 的 Blob 下载实际行为、私密浏览/低存储情形、真实多标签并发，以及损坏档的人工恢复工作流。
- 不提供无损自动恢复承诺；用户主动重置后，旧内容可能不可恢复。
