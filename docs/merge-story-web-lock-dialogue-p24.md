# P24 · 剧情对白存档的统一 Web Locks 协议（仅 Draft 分支）

## 缺口与修复
P22–P23 已覆盖经营工作台普通写入和确认重置，但剧情对白的首次初始化、完成剧情、确认重置仍直接使用原文 CAS。两个同源标签在支持 Web Locks 的浏览器中可能同时触发对白写入。P24 新增 `dialogue-write.mjs`，将三种对白写入统一放在 **同一个故事存档键对应的独占锁** 内，同时保留 `writeStorySave` 的原文比对和再次读取。

页面等待锁期间暂停新的选择、完成与重置操作；其他标签修改对白存档或页面从后台恢复检测到变化后，递增失效序号，排队中的写入在锁内安全放弃。原有异常存档导出与用户确认重置提示保留。正常模式和经营工作台存档均不读写。

## 自动化覆盖
`tests/merge-story-web-lock-dialogue-p24.test.mjs`：双标签互斥选择、完成与重置双向竞态、首次初始化、异常存档确认重置、锁 API 拒绝、无锁 CAS 降级、锁排队期间失效、UI 入口及按钮门禁。

## 未解决
Web Locks 只协调**支持并参与同一锁名**的同源标签；不支持该 API 的 iPhone Safari/微信 WebView 继续使用 CAS 降级，仍无跨标签真正原子事务。旧版标签、浏览器终止时序、文件下载、BFCache/真机 UI 和剧情品质尚待专项验收。此提交不宣称真机通过或达到发行标准。
