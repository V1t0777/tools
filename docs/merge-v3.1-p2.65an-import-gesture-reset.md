# V3.1 P2.65an｜导入选择器与旧触控/重置确认竞争（未发布）

## 问题
普通模式已阻断文件选择/读取期间的经营写入，但重置的同步确认框结束后只核对页面及 importEpoch：若 WebView 的嵌套回调在确认期间打开文件选择器，新的选择器不会递增 epoch，旧确认可能继续发起重置。与此同时，开始选择文件前的材料拖拽、选中格和动态按钮仍可能保留旧手势；选择器期间产生的 pointerdown 在取消后可能转成迟到的 click。

## 本轮修复
- 重置确认后再次检查 importPending，拒绝在新选择器/文件读取仍活跃时重置，保留原始存档与备份。
- 打开原生选择器前撤销旧拖拽与选中格，重新渲染以失效旧动态按钮，避免旧手势在取消后继续操作。
- 导入未结束时拒绝棋盘触摸选择和 pointerdown，并吞掉选择器期间的迟到兼容点击；用户取消后必须重新触摸才可生产。

## 验证边界
新增三个实际普通模式 HTML 入口 DOM 故障注入：确认期间嵌套打开导入、拖拽后打开导入及迟到点击、导入期间触控后取消并新触控恢复。断言原始普通存档零意外写入、剧情命名空间隔离和取消后的可操作性。全仓库 Node、scripts/security-check.sh、部署隔离及完整 Git 历史密钥扫描以最终 SHA 的 GitHub Actions 实际结果为准。

这不是 Safari/微信 WebView 实机验证；Node DOM 夹具不能证明真实原生文件选择器的事件顺序。Web Locks 不使 localStorage 成为跨标签原子事务。保持 PR #58/#59 Draft/Open，不改 main、正式导航/白名单、云服务或线上数据，不部署、不发布。
