# 云屿百物铺 P3.8 — 只读整理提示接入（未发布）

## 本轮目标
把 P3.7 的可恢复性诊断转成玩家主动请求的提示 UI，解决 P3.4 压力模型中“玩家不知道可以合成或收纳”的可用性问题。**不修改合成、订单、仓库、经济、存档结构，不制作新美术资源。**

## 变更
- `merge/board-guidance.mjs`：将 `diagnoseBoard` 输出映射为订单按钮、合成格子、仓库取出、材料收纳、仓库扩容、工坊和等待等中文建议，含存档版本标记。为纯函数，绝不产生修改状态的操作。
- `merge/main.mjs`：在手动点击“整理提示”后显示标记；操作完成、重置、跨标签换档时取消旧提示；体力随时间更新时重新评估。
- `merge/index.html` 与 `merge/style.css`：棋盘上方添加 44px 高的触摸按钮、常驻文字提示、无障碍状态通知及轻量高对比高亮。全局支持 `prefers-reduced-motion`。
- `tests/merge-board-guidance.test.mjs`：覆盖可交订单、同阶合成、仓库解困、金币扩容、无法恢复时保留存档、等待、纯函数不变式等 10 项。

## 明确的限制
1. 提示是**候选操作**，从不自动执行、扣费、删除或重置存档；用户仍需主动点击，执行时已有 P2 规则再次校验。
2. 不能仅因棋盘拥挤或一次“未整理”就断言永久死局；仅在 P3.7 定义的严格条件下提示当前无合法释放空间的步骤。
3. 这是 P2 离线试玩 UI，不接入 P3.x 在线同步队列，不上传本地金币。
4. 没有真实手机 Safari / 微信浏览器触控验收和生产云端联调；静态/Node 测试并不替代实机验收。
5. 如果 P3.7 诊断调整，应同步回归此模块与既有满盘压力模型。

## 发行边界
用户未明确授权之前，保持 Draft PR；不合并 main、不修改构建白名单或正式导航、不部署 GitHub Pages、Cloudflare、Edge Function、不执行 Supabase SQL，不推进美术。
