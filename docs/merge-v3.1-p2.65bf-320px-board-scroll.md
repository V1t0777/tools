# P2.65bf｜320px 极窄屏合成棋盘触控目标收口（2026-10-29）

## 问题与改进
此前 320 CSS px 视口下，普通经营模式的 7 列棋盘格约 36–37px，未达到 44px 的触控目标。7 列 × 44px 加间距无法同时完整放入 320px 屏幕。本轮不缩小格子、不改变引擎或存档，而是在 **≤360px** 时让棋盘所属区域局部横向滚动；棋盘每格固定 44 CSS px，页面本身仍不出现横向溢出。

极窄屏允许浏览器接管原生平移手势（`touch-action:auto`），因此材料拖拽可能被浏览器作为滚动取消；玩家仍可使用既有的**先点材料、再点目标格**完成合成/移动。此限制只作用于 ≤360px，375px 及以上保留原来的拖拽手势。没有新增按钮、奖励、经济数值或任何作弊能力。

## 新增自动化门禁
真实 Chromium 的 320/375/390/430/768px 移动视口测试统一要求棋盘格宽 ≥44px，仓库触控格 ≥44px、主要按钮高 ≥44px、无整页横向溢出。320px 的棋盘属于有意局部滚动容器，因此不把容器内暂时不可见的棋盘格误判为页面级裁切；必须证明局部滚动范围 >0，且滚动后第七列完全可进入视口。其余按钮仍严格检查页面裁切。保留既有真实 Chromium CDP 390px 轻触、拖拽、触控取消、后台恢复、Web Locks、BFCache 与存档恢复回归。

## 风险与发行边界
本轮局部滚动的可达性属于真实 Chromium 布局/脚本验证，不等于 **320px 物理触控滑动**、iPhone Safari 或微信 WebView 真机验收；极窄屏下的滚动与点选合成仍需实机确认。若无法平滑滚动、误触或影响纵向滚动，应阻断发行并修复，不可仅以 Node/Chromium 自动化代替。
