# 云屿百物铺 — P0/P1 研发记录

状态：开发原型 / 未发布 / 不涉及 Supabase。

## 目标与边界

- 以原创物品、故事和 UI 参考二合经营游戏的机制，不使用其他游戏的图片、音乐、文本或商标。
- 新增独立 `merge/` 目录；保留现有小游戏、静态部署白名单、CSP、账号及数据库隔离。
- 本原型只在开发分支提供源文件，**不**加入 `scripts/build-public.sh` 或 `cloudflare-secure/build.sh`，也不新增正式游戏导航入口。
- 实现 P1 基础体验：7×8 棋盘、三条原型合成链、拖动与点击操作、生产器、体力恢复、三张订单及本地存档。
- 项目架构优先维持仓库已有原生 JS 约定。`engine.mjs` 纯逻辑独立于渲染，后续可在验证性能后接 Phaser 3 场景；目前只用 DOM/CSS 绘制原型，不提前引入运行时依赖。

## 试玩

在仓库根目录运行 `python3 -m http.server 8080`，通过浏览器访问 `http://localhost:8080/merge/`。ES Modules 不建议使用 `file://` 直接打开。移动端请用同一局域网的受信本地服务器测试。

- 点击两件相同等级的物品合成下一阶；不同物品交换，空格移动。
- 手机可拖拽物品，桌面可用鼠标拖动；键盘支持 Tab + Enter 逐格操作。
- 点击三个 🧺 生产器获得物品，消耗体力；每次生成器储量 12，耗尽冷却 45 秒。
- 有订单物品时，可交付以换取原型金币与经验。
- 自动保存到当前浏览器 `localStorage`，不与工具箱账号关联，不形成权威云端货币。

## 规则与稳定性

- 棋盘 56 格、最高等级 6 阶；合成只保留目标格的实例 ID 且每次事务 revision +1。
- 物品 ID 单调递增，不因拖拽重排；拒绝错误坐标、同格动作及最高阶合成。
- 产物：75% 1 阶、22% 2 阶、3% 3 阶。随机值作为参数注入以便测试。
- 体力上限 80、每三分钟恢复 1 点；进入游戏和定时刷新时根据真实经过时长结算。
- 本地存档含固定 schemaVersion 与不变量校验。损坏 / 旧版本存档不会静默解释成正确存档（当前退回新试玩档）。
- 演示订单是可重复的开发测试内容，经济参数仅为示例，不等同 P2 完整数值系统。

## 进入 P2 / P3 前必需补充

1. 订单需基于解锁等级、可生产资源、棋盘库存估算成本，并配置软锁与保底。
2. 生产器状态、订单完成、货币和体力应使用服务端权威事务与操作幂等键；纯客户端状态不得直接导入正式云档。
3. 云存档数据分层、跨设备 revision 冲突检测、RLS、明确定义的 API GRANT，且默认 deny 重要表写入。
4. 统一内容版本和迁移策略；正式资源以原创图集替换 emoji 占位图，进行性能评估及降级策略。
5. 验证低端 iOS Safari / 微信内置浏览器的拖拽命中，特别是 `pointercancel`、滚动冲突与安全区。
6. 将新游戏加入正式部署构建脚本、导航和白名单之前，必须另行审核授权，不能跳过原有隔离门禁。

## 当前验证

```sh
node --test tests/merge-engine.test.mjs
```
