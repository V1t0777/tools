# 《云屿百物铺》P51 · 每日事件跨标签同步不打断主支线阅读（未发布）

## 实际问题
P50 允许被动标签接纳另一个标签写入的**字节完全一致**每日事件固定记录，但 UI 会无条件关闭当前对白、清除尚未提交的主线或人物支线选择。用户即使没有改变章节，也可能在 iPhone 两个标签间丢失阅读位置与已选选项。

## 小范围实现
- 在 `merge/story/daily-pin-reconcile.mjs` 新增只读 `canKeepDialogueAfterDailyPin`。只有已通过 P50 精确字节核对的每日固定记录，且对白属于当前首卷的**同一条目对象**、当前剧情存档有效、该主/支线仍可阅读或已完成，才允许保持弹窗。
- `merge/story/ui.mjs` 被动接纳每日事件时保留符合条件的主/支线弹窗与已选按钮。每日事件弹窗、锁定章节、同名 DLC 对象和其他任何存档冲突继续关闭或阻断。
- 不修改章节解锁、经济资源、奖励、存档结构、事件选择算法、浏览器部署路径或线上数据。

## 验证
新增 `tests/merge-story-daily-dialog-preserve-p51.test.mjs` 六项：真实被动固定事件→主线选择继续提交、已读主线与可读支线、事件/锁定章节拒绝、DLC 对象身份与损坏存档拒绝、只读不变性及 UI 接线合同。

同步上游 P2.61e 原始存档恢复锁回调安全加固，保持独立开发分支与上游一致。最终必须以当前提交 SHA 的 GitHub Actions 全仓库 Node 回归、静态安全/部署隔离、完整 Git 历史密钥扫描三项真实结果为准。

## 剩余风险
本轮只改善**已通过精确一致性核验的被动事件固定**。不自动合并不同剧情选择、跨日结果或旧客户端无锁写入；Web Locks 不可用环境仍有 CAS 非原子竞争窗口。真实双标签、iPhone Safari、微信 WebView 尚未验收；普通模式持锁模块尚未全面接入 `merge/main.mjs`。PR #58/#59 保持 Open/Draft，不合并 main、不发布、不触及线上 Supabase。
