# P89｜首卷四章持久化往返与跨标签阻断回归（未发布）

## 本轮目标

在已有 P69 真实引擎四章通关模拟之外，补充真实故事存档和独立经营存档的逐节点写入、重新读取、门槛校验。此前 P69 在里程碑回调中主要使用内存中的剧情进度；本轮新增测试避免把内存通关误当作存档恢复通关。同步普通模式 P2.65x 的下载 URL 撤销失败配额保护，不修改剧情数值或存档结构。

## 可验证场景

1. 三个确定性种子使用现有 `novice-supplies` 真实 7×8 经济引擎走过首笔委托、花园、港湾、门面四个节点。每个节点将经营状态写入 `STORY_WORKSHOP_KEY`、重新读取并验证；逐段完成首卷十二个主线场景，使用 `STORY_SAVE_KEY` 的正式写入/读取路径。未完成下一个真实经营门槛时，剧情指引必须停留在工作台；全部完成后才返回 `complete`。支线和日常事件不应被强制完成。
2. 第一章后注入带孤立 UTF-16 代理字符的损坏工作台记录：剧情指引必须阻断，正常写入不得静默修复；用户主动授权的只读取证应保留原始代码单元，两个剧情存档及普通经营不得被意外覆盖。该测试不触发真实浏览器下载。
3. 另一个标签页在第一笔委托后通过真实仓库收纳操作更新经营存档：旧工作台快照不能授权剧情完成，旧操作不能写入对白；重新读取快照并重新确认条件后可以继续，普通模式资源不受影响。

## 安全与边界

- 本轮只添加测试及中文文档；普通模式同步仅限经 SHA 核对的三个上游文件，保留双父合并历史。**不修改 main、正式导航、部署白名单、线上 Supabase、Edge 或任何发布配置**。
- 全仓库 Node、`bash scripts/security-check.sh` 与完整 Git 历史密钥扫描均须以本轮新 SHA 的 GitHub Actions 三门禁结果为准。测试文件语法检查仅证明语法，不是功能通过。
- `localStorage` 非跨标签原子事务；此测试验证顺序写入和锁内重读，不能证明极端同时写入安全。
- 真实 iPhone Safari / 微信 WebView 的原生确认、BFCache、多标签、`.txt` / `.utf16.json` 文件落盘，以及 Windows 离线完整手工通关仍为 P0 验收阻塞；不能用 CI 冒充真机结果。
