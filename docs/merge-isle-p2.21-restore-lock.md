# 《云屿百物铺》P2.21 — Web Locks 普通模式恢复协调适配器（未发布）

## 工程增量

- 新增 `merge/save-restore-lock.mjs`，通过显式传入的 Web Locks API `lockManager.request` 申请同源命名的独占锁，受保护地调用 P2.20 恢复提交函数。
- 调用者未确认、Web Locks 不可用、锁被其他参与方占用、锁模式不可信时均拒绝恢复；采用 `ifAvailable:true`，不会无限等待或者在失败时退化为无锁写入。
- 上游恢复仍在锁内重复进行 V3 文件校验、原存档基线比较、旧进度回退确认、独立原始备份和写入后读回验证；锁提供的是**参与者之间的互斥**，不是 `localStorage` 的事务 CAS。
- 锁请求在提交后异常终止会返回 `RESTORE_OUTCOME_UNCERTAIN`，不得盲目自动重试或回滚。
- 本轮**不接入玩家导入按钮**，不访问 `navigator.locks` 全局，不自动发起恢复，也不读取剧情存档或云端内容。

## 重要限制与实施顺序

1. 普通游玩中的 `saveLocal`、确认重置，以及剧情/普通界面的其它持久化路径目前**没有全部采用这个同名锁**。其它未参与者依然可能在加锁期间写入，故不能据此宣称解决全部跨标签竞态。
2. 部分 WebView 或非安全上下文不提供 Web Locks；正式 UI 需要清楚告知不可用，不得回退到无保护导入。
3. 下一阶段应通过统一普通模式所有读改写路径和恢复路径的锁纪律，并保留原始字节比较；涉及玩家 UI 前必须进行真实双标签/浏览器故障注入及 iPhone Safari、微信 WebView 测试。
4. 此锁只保护同源且自愿采用同一命名锁的浏览器客户端，不提供跨设备/云端一致性，也不自动获得用户确认。
5. 原始备份仍保存在同一浏览器 origin；需要外部下载与真实文件恢复演练。
