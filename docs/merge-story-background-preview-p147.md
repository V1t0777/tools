# P147｜剧情工作台长时间后台恢复的只读时间预览（未发布）

## 修复范围
移动端 Safari/微信 WebView 长时间进入后台后，页面可能保留冻结前的 DOM：体力仍显示为 0、工坊仍显示“冷却中”，尽管离线引擎按真实时间已经自然恢复；体力已恢复满额时，旧界面还可能错误地允许点击恢复道具。本轮不修改经济公式或存档协议，仅在剧情工作台每次 render（含 pageshow 恢复）时通过已有 `advanceTime(state,Date.now())` 计算**只读展示快照**。

- 体力数字、工坊剩余次数和冷却卡候选列表使用只读展示快照；恢复到满体力时禁用体力补给按钮，避免误导玩家。
- 实际生产、补给消耗、建筑付款仍基于原始 `state`，由现有引擎在明确操作时推进时间，再经过 Web Lock、原始字节 CAS 和发布后复核。渲染不写 localStorage，不消耗卡片，也不增加 revision。
- 没有新增计时器、后台轮询、云同步或自动赠送。恢复后的显示属于客户端时间估算，设备时钟被人为调整时不提供可信计时保证。

## 验证
`node --test tests/merge-story-warehouse-upgrade-p145.test.mjs`：新增三项 P147 场景：①后台恢复展示3点体力及12次工坊充能，操作前0写入、首次生产只写一次；②自然恢复满体力后禁用恢复饮料且不改原存档；③尚未结束的冷却保持冷却中且不自动使用冷却卡。继续验证普通模式与剧情对白存档隔离。全仓库 Node、静态安全/部署隔离和完整历史密钥扫描以最终 SHA 的 GitHub Actions 为准。

## 风险与发行边界
这是 Node 事件型 DOM 模拟，并非真实 iPhone Safari、微信 WebView 的后台冻结或系统时钟实机验收。普通模式 Chromium 触控偶发超时、Windows 离线运行和损坏存档下载真实落盘仍是发布阻塞。PR #59 保持 Draft/Open；不合并 main、不修改正式导航/部署白名单、不部署 Pages/Cloudflare/Edge、不接触生产 Supabase。所有研发提交以 `[CF-Pages-Skip]` 开头。
