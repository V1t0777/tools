# P2.61f · 跨标签存档冲突时撤销过期棋盘交互（未发布）

## 缺陷
普通模式已能阻断删除、损坏、旧版本及同版本经济冲突后的写入，但 storage 监听器只取消拖拽，不清除旧棋盘选中项及整理高亮，可能继续展示过期操作指引。

## 单一安全增量
仅修改真实页面的 storage 冲突分支：在四类异常分支（存档不可用、已阻断页面再次收到变更、远端旧版本、同版本经济差异）统一取消拖拽、清空选中项及整理高亮并重新渲染。保留原始内存状态和 persistedRaw，不写入存储、不自动合并或重置。健康的相同原始存档与无关事件仍不触发额外渲染。

## 验证与限制
扩充 tests/merge-storage-event-policy.test.mjs 的既有真实监听器 Node VM 回归，核对四类异常下的渲染、选中项、高亮、拖拽取消与原始状态/原始字节保全。以最终 HEAD 的 GitHub Actions 全仓库回归、静态安全/部署隔离及完整历史密钥扫描为准，不以旧 SHA 或本地模拟替代。

本次不解决同步 persist() 的跨标签原子性，后续仍须整体迁移启动、动作、时钟与重置至统一 Web Locks 事务；也未完成真实 iPhone Safari、微信 WebView 与双标签端到端验收。PR #58 保持 Open / Draft；不合并 main、不部署、不操作线上数据库、不修改正式导航或部署白名单。
