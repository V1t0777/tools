# P73 · 普通模式恢复与剧情双存档隔离回归（2026-10-27；未发布）

## 背景与实际范围

PR #58 上游 P2.65g–h 增加普通模式多点触控保护与受锁保护的存档恢复。剧情 PR #59 在逐文件比对共同祖先 blob SHA 后，将上游 7 个未在剧情分支改动的文件安全合入；双父提交保留两个分支历史，未强推。

本轮新增 tests/merge-story-normal-restore-isolation-p73.test.mjs，直接调用普通模式 createNormalPageRuntime.restore、真实故事对白写入、剧情工作台引擎和独立存档接口，覆盖：

1. 正常恢复只替换普通模式存档并保存原始普通模式备份；故事对白与工作台原文字节不变，恢复后两种剧情写入仍可继续。
2. 即使剧情工作台已有损坏原文，普通模式恢复也不得暗中修复、覆盖或重置该记录；正常故事对白仍可独立推进。
3. 普通模式恢复 Web Lock 被占用时，普通模式不能写入，但健康的剧情写入不得被错误锁死；之后普通模式可在明确确认下重试。
4. 将真实剧情进度 JSON 误选为普通模式恢复文件时，必须拒绝且不能修改任何存档或备份槽。

这些是独立的离线 Node 模块回归，不是模拟浏览器触控，也不证明浏览器 localStorage 具备原子跨标签事务。真实 iPhone Safari/微信 WebView 的多标签、后台恢复、存档下载落盘与原始备份仍需用户设备验收。

## 发行边界与门禁

只改独立剧情研发分支的专项测试与中文记录；不改 main、正式导航、部署白名单、线上 Supabase，不发布 Pages/Cloudflare/Edge，PR #58/#59 均保持 Draft。所有提交使用 [CF-Pages-Skip] 前缀。最终 SHA 必须完成 Node、静态安全/部署隔离、完整历史密钥扫描 3 项检查，并核对没有 Cloudflare 部署检查；若 CI 失败则记录并修复，不能将待运行当成通过。
