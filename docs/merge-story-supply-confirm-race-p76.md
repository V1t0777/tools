# 《云屿百物铺》P76｜剧情补给确认期间的旧存档阻断

范围：仅独立剧情分支 Draft PR #59；不涉及普通模式、经济参数、正式导航、部署或线上数据。

## 问题与修复

剧情工作台 P75 在购买补给可能动用下一处建筑金币储备时使用原生确认框。确认框打开前，旧页面可能已经落后于其他标签页的工作台原始存档；确认框期间，另一个标签页也可能改变金币。浏览器的 `storage` 事件并不保证在本页点击回调之前送达。

- 打开风险确认框前，先只读核对工作台当前原始字节；已变化则阻断，避免用旧金币预算询问玩家。
- 用户取消确认后，再次核对原始字节；如果确认框期间出现外部修改，撤回「已取消购买，金币未扣除」的旧页面提示，改为保护性阻断和重新打开核对。
- 用户同意购买后，原有 `commit()` 仍执行精确原文预检、Web Lock、CAS、写后与渲染后复核。没有新增自动重试、扣款补偿或绕过确认的途径。
- 现有成功购买、正常取消、限购库存、双模式存档隔离不变。

## 专项测试

在真实 `merge/story/workshop.mjs` DOM 测试夹具中新增 3 项故障注入：点击前外部修改（不应弹窗）；确认框期间外部修改并取消（不应显示旧取消成功提示）；确认框期间外部修改并同意（不应扣款）。每项均核对剧情金币、补给限购、零本页写入、普通经营及对白存档不变。

## 发行风险与边界

此测试仅模拟单进程事件顺序，不能证明跨进程 `localStorage` 的原子性；仍需 iPhone Safari、微信 WebView 的原生确认框、后台恢复、多标签并发和异常存档下载落盘实机验收。真实 Web Lock 与跨标签 CAS 的竞态窗口仍须在发行风险台账中保留。
