# 《云屿百物铺》V3.1 · P2.65f 移动端拖拽失效与完整重绘保护

**范围：PR #58 普通经营独立 Draft 分支，未发布。** 本轮仅处理离线首发的触控 P0 风险，不修改剧情源文件或部署配置。

## 发现的问题

Web Locks 与存档原始字节核验可以阻止跨标签的过期写入，但不能单独防止**同一页面内的旧拖拽事件**。在材料拖拽过程中，玩家可能通过键盘、其他控件或异步事务引起完整重绘；旧 `drag.origin` 仍指向上一帧的格子，随后的 `pointerup` 若命中新棋盘，会把旧手势解释为对新棋盘的合成/移动。只读的“整理提示”重绘也可能留下悬浮拖拽影子。移动端浏览器还可能在滚动或失去指针捕获时只触发 `lostpointercapture`，而没有 `pointercancel`。

## 修复范围

1. 所有完整 `render()` 入口在更换棋盘 DOM 前同步取消现存拖拽，清理悬浮节点并屏蔽取消手势的迟到兼容点击；计时器的无变化资源刷新不受影响。
2. 监听 `lostpointercapture` 并复用既有取消路径。正常 `pointerup` 已清除拖拽时，该事件不会重复取消或提交。
3. 新增实际 `merge/index.html` 入口的 DOM 回归，覆盖整理提示引发的重绘、同页生产事务异步重绘、指针捕获丢失与后续真实新手势恢复；断言普通模式原始存档及剧情命名空间不被过期事件改写。

## 验证及发行阻塞

本地环境当前无法通过 DNS 克隆仓库，因此不得将孤立模拟视为全仓库回归。提交后必须按**新 SHA**核对 GitHub Actions 的全仓库 Node、`bash scripts/security-check.sh` 与静态部署隔离、完整 Git 历史密钥扫描；任何未通过均不能宣称验证完成。Node DOM 事件模拟不是 iPhone Safari 或微信 WebView 真机验收；需在真机检查拖拽中打开整理提示、切换后台、手势中断、丢失捕获及下载落盘。Cloudflare Pages 预览部署配置仍缺独立核验。保持 PR #58/#59 Open/Draft，不合并 main、不改正式导航/部署白名单、不部署、不执行线上 Supabase SQL。
