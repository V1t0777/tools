# 《云屿百物铺》P2.17 — 普通模式确认重置的存档基线校验（未发布）

## 问题

旧 `saveLocal` 在 `allowReset:true` 时跳过 `expectedRaw` 比对，导致玩家即使确认了重置，也可能覆盖同一浏览器另一标签页刚刚保存的有效普通模式存档。

## 修复边界

- 用户主动点击确认重置**仍不足以**授权覆盖未见过的存档：必须同时携带已读取的 `expectedRaw`（包括新存档的 `null`），并和重置瞬间读取的当前原始数据一致；未提供基线、存档后来发生变化时均拒绝。
- `loadLocal` 检测损坏、超限存档时将已读取的原始 `raw` 返回给调用方（不解析成有效状态），避免重置只能依赖绕过校验；旧版迁移备份/写入失败时也保留其已观测原文字节。
- 重置写入失败时，预览页撤销尚未持久化的空白棋盘展示，明确提示重新打开页面核对，不能谎称重置成功。
- 保留普通模式原存档键及 V3 结构，不涉及剧情模式存档、云端账户、货币、体力、奖励或正式导航。

## 专项回归

`tests/merge-storage-safety.test.mjs` 扩充：双标签同 revision 写入后拒绝过期重置、损坏/超限原文字节变化后不覆盖、缺失基线拒绝、用户确认且当前原文匹配时可以重置、失败时页面状态回退。

## 残余风险和发布门禁

浏览器 `localStorage.getItem` 与 `setItem` 仍不是跨标签原子事务；另一个标签可能恰好在两次调用之间写入。本增量只能修复**已发生并可观察到的**旧基线覆盖，不代表已经实现事务 CAS 或跨设备冲突解决。正式 RC 仍需跨标签竞态测试、iPhone Safari/微信 WebView 真机测试、原始存档导出与可信恢复、回滚演练。
