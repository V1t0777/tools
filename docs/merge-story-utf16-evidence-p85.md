# P85｜剧情损坏存档 UTF-16 无损证据导出（未发布）

日期：2026-10-28；仅 Draft PR #59 剧情侧与普通模式 PR #58 的安全前向同步。

## 故障与修复
localStorage 保存 JavaScript UTF-16 字符串。若损坏存档含孤立高/低代理项，直接传给 Blob 的 UTF-8 编码会将其替换成 U+FFFD，造成所谓“原始备份”丢失原始代码单元。

- 正常 Unicode（含合法 emoji 代理对）保持原始 .txt 导出。
- 仅遇孤立代理项时，剧情对白/工作台改用 `.utf16.json` 证据封装；`format:yunyu-story-evidence-utf16-v1` 与 `raw` 由 JSON.stringify 保留全部 UTF-16 代码单元。此文件是人工取证封装，**不是可直接导入的游戏存档**。
- 两处 UI 均明确“已尝试下载”及需检查设备文件落盘，不将锚点点击冒充下载成功。原始浏览器存档不写回、不清除、不上传。
- 新增 Node 测试覆盖普通文本、emoji、孤立高/低代理项、浏览器 Blob 编码后的 JSON 反解、两模式存档隔离及 UI 文案。

## 上游同步与边界
本轮先比对共同祖先和四个文件路径，无故事侧重叠，双父提交同步普通模式 P2.65s 原生取消与 P2.65t 恢复前备份反馈。保持双方 Draft/Open；不合并 main，不部署，不修改导航/部署白名单，不执行线上 SQL/Edge。

## 待验收风险
Node/DOM 不代表 iPhone Safari 或微信 WebView 的下载落盘。需在真机对 .txt 与 .utf16.json 分别验证文件存在、可读取及 UTF-16 反解一致性；浏览器可能禁止下载或丢失临时 Blob URL。跨标签 localStorage 非原子事务问题仍存在。11 月 10 日目标仅为争取候选终审，不是发布授权。
