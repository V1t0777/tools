# 云屿百物铺 V3 · P2.61i 普通模式动作输入纯度校验（未发布）

## 问题与目标
P2.61h 已要求未来锁内玩家动作返回新对象且 revision 恰好递增一次，但仍可能出现动作先原位修改传入的棋盘、金币等对象，再返回一个新的外层状态对象的情况。此类动作违反现有“同步、无副作用引擎动作”契约，且单纯比较顶层引用无法识别。目标是避免错误适配器将被原位改动的基线视为可信。

## 单一工程增量
- 在 `commitNormalActionWithLock` 已确认原始存档基线后，先序列化已验证的输入状态。
- 调用同步动作后再次序列化输入；若不同，返回 `ACTION_MUTATED_BASELINE`，不调用存档写入、不返回可发布状态。
- 即使动作声称失败，也不得静默修改输入；已有正常引擎动作仍按原有 revision、CAS、写后回读流程执行。
- 该检查是未来异步 UI 接入的防御性契约，不是防作弊或跨标签原子写入的替代品。序列化增加少量每次动作的 CPU 开销，真实移动端性能尚未测量。

## 专项回归
`node --test tests/merge-normal-action-transaction.test.mjs`：新增嵌套棋盘原位修改并返回新外层状态、失败动作原位修改金币两种场景；均要求原始字节不变、零写入。既有真实引擎正常动作测试应继续通过。全仓库回归、静态安全/部署隔离、完整 Git 历史密钥扫描必须以本次最新 HEAD 对应的 GitHub Actions 为准。
