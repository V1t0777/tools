# V3.1 P2.65as｜普通棋盘旧触控许可与发行阻塞清单（未发布）

## 真实问题与修复
普通模式常驻按钮已有触控代次保护，但棋盘生产器/空格的 `pointerdown` 不会形成材料拖拽。文件选择器、BFCache、或 Web Lock 等待期间，旧触控可能在页面恢复/保存完成后以兼容 `click` 到达；旧实现仅在存在材料拖拽时设置 `ignoreNextClick`，因此可能错误生产、消耗体力或选择旧格子。

本轮为棋盘指针建立仅用于 UI 的许可，绑定页面交互代次、渲染代次和格子位置；拒绝导入中、后台、存档未就绪、保存中、非主指针、无效目标的指针；`pointercancel` 和 `lostpointercapture` 撤销许可。迟到兼容点击只消耗旧许可，不进行引擎操作。正常新触控和键盘 `detail===0` 激活仍可使用。不更改经济、存档结构或 Web Locks 协议。

## 专项验证
`tests/merge-locked-page-dom.test.mjs` 增加 4 项实际页面入口 Node DOM 回归：
1. 生产器按下→打开/取消原生文件选择器→迟到点击：零额外写入，新触控可生产。
2. 生产器按下→pagehide/BFCache pageshow→迟到点击：零额外写入，新触控可生产。
3. 生产事务等待 Web Lock→第二次按下被拒→首笔完成→迟到点击：无重复生产，新触控可生产。
4. 生产器 pointercancel→迟到点击：无写入，重新按下可操作。

测试只能模拟事件顺序，不等于 Safari/微信 WebView 真实设备行为。必须核对最终 HEAD 的全仓库 Node、`bash scripts/security-check.sh`、静态部署隔离与完整历史密钥扫描全部通过。
