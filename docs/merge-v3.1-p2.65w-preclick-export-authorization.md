# 云屿 V3.1 P2.65w｜下载发起前最后一次授权复核（2026-10-28）

## P0 问题与范围

P2.65v 已在创建 Blob 前检查原始存档/备份是否改变，但浏览器的 Blob 构造、Object URL 创建、DOM 插入仍可能触发同步副作用。原先的检查与原生 a.click() 之间存在可观测的窗口：页面可能进入 BFCache，或其他标签已替换来源字节，却继续请求旧快照下载。

## 本轮实现

- `merge/save-download.mjs` 新增可选 `authorizeClick`：锚点已插入、原生 click 之前同步执行，必须严格返回 `true`；异常、false 或不支持的授权参数均拒绝。拒绝时撤销新建 Blob URL、释放并发额度、移除锚点，不发起下载。
- `merge/main-locked.mjs` 普通存档、异常重置前备份、恢复前备份三条入口统一执行页面可见/BFCache 与来源原始 UTF-16 码元复核。既有第一次复核保留，第二次复核缩小时序窗口。
- 三类拒绝均显示明确中文提示；只读、不覆盖存档、不更改经济、不触碰剧情命名空间。

## 验证与剩余风险

- Node 专项覆盖：DOM 插入期间来源改变、授权回调抛错/参数异常、正常授权、三种实际 HTML 下载入口、下载准备时 pagehide。
- 提交后必须在最新 HEAD 核实全仓库 Node、`bash scripts/security-check.sh`/部署隔离、完整历史密钥扫描；本文件本身不代表 CI 已通过。
- 本改动不是跨进程原子快照：授权回调与浏览器实际消费 Blob URL 之间仍可能竞争。成功只表示已请求下载，不表示 iPhone Safari/微信 WebView 已将文件落盘。真实双标签和手机验收仍为发行阻塞。
- PR #58/#59 继续 Draft/Open；不得合并 main、发布或操作线上 Supabase。
