# 云屿 V3.1 · P2.65cd｜死局解围跨标签与确认期竞态回归（未发布）

## 本轮目标

补齐普通经营模式「死局解围」的两种高风险竞态，避免把已失效的触控和确认应用于其他标签页的新存档。只扩展现有真实 Chromium 回归，不改动经营规则、存档结构或剧情源文件。

## 场景一：主标签始终在前台

从有效的满盘满仓存档启动，主标签选中原料并按下解围按钮；第二个同源标签在**真实浏览器 Web Locks 独占锁**内调用正式 `discardDeadlockedMaterial` 引擎，成功弃置另一件原料并写入有效 V3 存档。主标签不隐藏，收到 storage 事件后采纳新进度，随后迟到的旧触控不得弹出确认或覆盖新存档。最后在主标签执行一次新的正常生产，确认恢复操作能力。剧情存档及两种备份原字节不变。

此测试使用第二标签的真实锁、存储与引擎，但为了在主标签保持前台，第二标签不走被隐藏页面禁止操作的 UI；不能冒充两个可见窗口的真人触控测试。

## 场景二：同步确认框期间基线被替换

故障注入在 `window.confirm` 返回 true 之前，用一个结构合法、revision 递增的新原始存档替换本地字节。确认后的旧解围意图必须拒绝，不允许再弃置任何原料，也不允许改写新字节或剧情、备份。此场景模拟不遵守 Web Locks 的旧标签或重入写入，**不**把故障注入描述为正常玩家操作。
