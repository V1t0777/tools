# 《云屿百物铺》P3.13 — 持久化云指令队列状态不变量（未发布）

> **范围**：只修改尚未接入正式游戏的 `merge/cloud/offline-queue.mjs`、独立 Node 回归测试和本文件。本轮不合并 `main`，不更新正式导航或部署白名单，不执行线上 Supabase SQL/迁移，不部署 GitHub Pages/Cloudflare/Edge Function，也不推进美术素材。PR #58 必须保持 Draft。

## 缺陷与威胁模型

离线队列原来用 `if (!raw)` 判断不存在 journal。真实 `localStorage.getItem()` 在**键不存在**时返回 `null`，而键存在但内容是空字符串 (`''`) 属于损坏；若将其当作首次启动，后续写入可能覆盖原始异常证据。浏览器磁盘故障、导入文件、错误的存储封装、非原子的跨系统复制都可能暴露这种不一致。

旧 `validJournal()` 也没有阻止以下不可能由正常串行处理生成的状态：

- `operationId` 的**大小写别名**（UUID 格式大小写不敏感，服务端标准化为小写，两个待决条目可能别名为同一幂等操作）。
- 第二条及之后待决指令已经绑定 `expectedRevision`、已有发送次数或退避时间（队列只能先处理第一条）。
- `attempts===0` 却存在 `nextRetryAt>0`，或尚无已验证服务器快照却已经固定 revision。
- `blocked` 非空但没有未决操作，无法知道原始需审核的操作。

## 修复策略

1. **仅 `raw === null` 初始化空队列**。空字符串、非字符串和长度异常均按 `storage-error` 处理，维持 fail-closed，不覆盖原始键值、不访问远端、不发送指令。队列坏损时界面沿用 P3.12 优先提示“请勿清理浏览器数据”。
2. 对待决 UUID 做不区分大小写的唯一性校验，不修改已经持久化的 ID，也不生成替代 ID。
3. 明确恢复不变量：只有队首允许被固定 revision、记录发送尝试或拥有退避时间；没有权威 `confirmed` 快照时不允许存在任何固定或尝试过的指令；退避时间大于零必须已有发送尝试；阻断状态必须与至少一条未决操作同时存在。
4. 只增强读取/写入前数据校验，不改变服务器交互、CAS、幂等重试或正式经济规则。合法的“首条结果未知 + 后续未发送”应当继续在重启后恢复并沿用原操作 ID；已有冲突阻断也必须合法保留。

## 验证

新增 `tests/merge-cloud-journal-invariants.test.mjs`：

- 缺失键与真实空字符串值的区别
- 错误存储封装返回非字符串时阻断
- 大小写不同、语义相同的两个 operation ID
- 队尾被提前固定、发送、设置退避
- 尚未尝试发送却有退避时间
- 从未读过服务器却预先绑定 revision
- 无未决操作却标记 conflict
- 两条合法队列：首条在服务端已提交但 ACK 丢失、第二条尚未发送，重启后首条原 ID 幂等重放、然后只执行第二条一次
- 确定冲突的 journal 在重启后仍保持阻断，不能自动补发

## 剩余风险

- `localStorage` 并非持久事务，实际设备掉电或浏览器数据被用户清理可能丢失记录；此时只能依赖服务端真实持久化幂等日志核验结果。
- 当前仅对 schema 和队列状态转移施加约束，不能证明本地内容从未被恶意用户伪造，更不能替代身份认证、RLS、服务端操作 ID 约束、事务 CAS 或防重复奖励逻辑。
- 遇到异常持久化记录本轮不会自动修复或删除；需另行设计只读导出与明确用户授权的安全恢复流程。
- 真实 iOS Safari、微信 WebView、多设备断网、后台回收以及正式 Supabase/Edge 服务没有上线测试，**本阶段不是发布许可**。
