# 云屿 V3.1 · P2.62 页面存档发布失效闭环（未发布）

## 目的
继 P2.61w 统一普通模式事务运行时之后，封闭“数据读取或重置成功，但渲染回调同步触发失效，页面仍返回成功”的边界。
该运行时尚未连接到正式 `merge/main.mjs`，不可称跨标签完整上线。

## 实施
1. 重置事务读取并验证成功后，UI 同步发布记录 epoch。若 `onVerified` 通过 `invalidate`、`block` 等再次触发存档失效，返回 `RESET_INVALIDATED`，永久阻断旧页面继续写入，不误报成功或重新设置 `ready`。
2. 外部存档同步为只读路径，对原始 `SAVE_KEY` 进行发布前、回调后的精确字节复核。回调期间发生覆盖，返回 `CURRENT_SAVE_CHANGED` 并阻断。
3. 外部同步回调期间如发生失效、阻断或重入事务，不返回“同步成功”，而返回 `RECONCILE_INVALIDATED` 并停止后续写入。
4. 新增五项自动回归：重置回调失效、重置回调阻断、外部同步回调失效、同步后存档覆盖、健康同步不退化。

## 安全与质量边界
- 不改动正常模式的现有同步页面、不改剧情模式存档、不改正式部署名单、不添加网络调用或数据库迁移。
- `onVerified` 必须同步且无异步副作用；禁用 Web Locks 的浏览器仍不能自动降级为无锁写入。
- 这些重复读回检查只缩小**发布期间**的失效窗口，并不使未统一采用 Web Locks 的旧标签操作原子化。
- CI 必须以本提交 SHA 的三项 GitHub Actions 实测为准；缺少真实双标签、iPhone Safari、微信 WebView、云端 RLS/CAS 验收，仍然不能视为发布候选版。
