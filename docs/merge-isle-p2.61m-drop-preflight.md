# P2.61m · 普通模式拖拽落点前再次核验原始存档

## 问题与范围
P2.61l 在触摸开始（pointerdown）前检查了原始存档，但用户拖动期间另一标签可能写入新进度，而 `storage` 事件尚未送达。此时 pointerup 仍会基于旧棋盘计算落点；尽管同步写入路径最终具有非原子 CAS 防护，仍会发生过期交互计算。此轮只修复真实页面的拖拽完成入口，不改变存档格式、经济数值、剧情或部署。

## 最小修复
- 已实际移动且未取消的拖拽，在获取落点与调用 `moveOrMerge` 前，复用现有只读 `revalidateResumedSave()` 比对当前原始字节。
- 检测到替换、删除、损坏或读取失败时，保持旧内存进度和原始字节不变，阻断操作并清除过期选择/提示；不执行写入、自动修复或合并。
- 先设置 `ignoreNextClick`，确保失败拖拽后延迟到达的合成点击仍被吞掉。
- 正常拖拽维持原行为；未移动、取消或已经阻断的拖拽不增加无意义存档读取。成功拖拽会额外进行一次只读检查。

## 验证
新增 `tests/merge-drop-preflight.test.mjs`，直接抽取真实页面的 `completeDrag` 与 `revalidateResumedSave`，测试拖拽期间被替换、删除、损坏、读取失败的存档、正常落点、取消/未移动及已阻断页面。要求未授权原始字节写入次数为零，失败时既不求值落点也不执行合成。并运行全仓库回归、静态安全/部署隔离及完整 Git 历史密钥扫描，以本轮 HEAD 的三项 Actions 结果为准。

## 未解决风险
落点前复核只是尽力而为的只读防护，**不是跨标签原子事务**。另一标签仍可能在最终读取后写入；同步 `persist()` 与启动迁移、游戏动作、计时器和重置尚未共同迁入 Web Locks。必须在同一事务边界整体迁移后才可宣称跨标签原子性。真实 iPhone Safari、微信 WebView、多标签端到端和 PostgreSQL/Edge 均未在本轮验收。

PR #58 与相关研发 PR 继续 Open/Draft。禁止合并 main、调整正式导航或部署白名单、发布 Pages/Cloudflare/Edge、执行线上 Supabase SQL/迁移、制作美术或作弊后门。
