# P2.61n · 普通模式非棋盘操作统一存档复核（未发布）

## 问题与最小范围
P2.61l/m 已覆盖棋盘点击、拖拽开始及落点，但委托交付、仓库取放/扩容、工坊/建筑升级、体力道具和金币补给按钮会直接调用页面的同步 `commit(result)`。这些操作依赖最终 `persist()` 的原始字节 CAS 防覆盖；然而当引擎返回失败结果时会在 CAS 前退出，无法及时发现已延迟的跨标签存档变更，页面可能继续展示过期交互状态。

本轮仅在真实页面统一动作入口 `commit(result)` 前增加既有 `revalidateResumedSave()` 只读检查，并在任何动作结果（包括引擎拒绝）处理前执行。已经阻断的页面不再读取或尝试保存。发现替换、删除、损坏或存储不可读时，清除旧选中/整理提示并暂停动作；不自动合并、覆盖、重置或删除原始存档。

## 兼容性与验证
不改经济参数、存档格式、同步写入策略、UI 文案体系、正式导航或部署。正常存档的按钮动作增加一次只读原始字节检查；后续同步 CAS 和写后回读保持不变。新增 `tests/merge-nonboard-action-preflight.test.mjs`，直接抽取真实页面的 `commit` 与 `revalidateResumedSave`，验证跨标签替换、引擎拒绝、丢失/损坏存档、正常成功以及已阻断状态。验证不应产生额外存档写入。

全仓库 Node 回归、静态安全/部署隔离及完整 Git 历史密钥扫描必须以本轮新 HEAD 的 GitHub Actions 三项实际状态为准；若任何一项未成功，不标记完成。

## 未解决风险
这只是按钮动作入口的只读预检，**不是 Web Locks 跨标签原子事务**。引擎结果目前在调用 `commit` 前计算，最终读写之间仍有竞态；同步 `persist()`、启动迁移、计时器和重置尚未整体迁入同一 Web Locks 协调边界。真实 iPhone Safari、微信 WebView、跨标签端到端以及 PostgreSQL/Edge 均未由本轮验证。

PR #58 与相关研发 PR 保持 Open/Draft。禁止合并 main、正式发布、修改部署白名单或导航、线上 Supabase SQL/迁移、Edge/Pages/Cloudflare 部署、美术和作弊后门。
