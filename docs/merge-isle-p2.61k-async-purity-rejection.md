# P2.61k · 异步动作与输入异常叠加时的 Promise 拒绝保护

## 问题与边界
P2.61j 已在普通模式未上线的 Web Locks 动作事务中拒绝异步动作并观察其 Promise 拒绝。但原实现先校验动作是否原位修改输入状态，再为异步动作挂接拒绝处理。如果错误的动作**同时**修改输入并返回一个会拒绝的 Promise，校验提前返回 `ACTION_MUTATED_BASELINE`，拒绝可能成为未处理异常。输入对象被错误地改成循环引用时，序列化还可能在挂接处理前抛错。

## 本轮变更
- 动作返回后，立即识别 thenable 并附加拒绝观察；**不等待、不重试、不采纳其异步结果**。
- 保留既有的同对象 `ACTION_REVISION_INVALID`、输入变更 `ACTION_MUTATED_BASELINE`、异步动作 `ASYNC_ACTION_NOT_ALLOWED` 错误码优先级。
- 增加两项故障注入：异步拒绝与原位修改叠加、异步拒绝与循环引用序列化异常叠加。均要求不写入、不发布新状态，并在 Node 测试运行器中不出现未处理拒绝。
