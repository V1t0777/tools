# P2.61v 普通模式四类写入路径的共享锁行为回归（未发布）

## 目标与范围
P2.61u 已加入“实际页面不得只迁移部分写入路径”的静态门禁。本轮针对尚未接入页面的四个现有事务入口，增加**组合行为测试**，验证启动迁移、玩家动作、计时器与重置使用同一排他锁时的运行结果。它不是把锁事务接入 `merge/main.mjs`，不改变现有普通模式同步 CAS 行为。

## 新增验证
- 模拟一个标签持有 `NORMAL_SAVE_LOCK_NAME` 时，四类事务同时请求锁均返回 `SAVE_LOCK_BUSY`；拒绝路径不读写存档，也不执行游戏动作。
- 模拟 Web Locks 不可用时，四类事务均返回 `WEB_LOCKS_UNAVAILABLE`，不触碰存储。
- 同一锁管理器下依次执行启动、真实引擎移动、无变化计时器、确认重置；检查每步返回可信原始字节、写后回读以及剧情存档隔离。
- 确认重置完成后，旧标签携带过期原始字节的玩家动作必须返回 `STALE_BASELINE`，不得求值或覆盖新档。

专项测试：`node --test tests/merge-normal-writer-coordination.test.mjs`。完整回归、静态安全与部署隔离、完整 Git 历史密钥扫描必须以本轮**新提交 SHA** 对应 GitHub Actions 为准；未完成三项前不标记通过。

## 重要局限与下一步
测试使用 Node 中的受控 Web Locks / localStorage 模拟，证明的是现有四个独立模块的协调契约，不等于浏览器真实多标签原子性。当前 `merge/main.mjs` 仍在使用未持锁的启动、游戏动作、计时器和重置；与旧版标签共存时，Web Locks 不能约束未参与锁协议的写入。后续必须一次性完成实际页面四路径迁移、异步初始化与 UI 阻断、故障注入，并进行 iPhone Safari / 微信 WebView 真实设备验证。
