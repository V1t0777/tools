# 《云屿百物铺》V3.1 · P2.65b 原始存档下载与移动端失败边界

**研发范围：** 普通模式独立 Draft 分支。HTML 入口已使用 `main-locked.mjs`；本轮不涉及线上发布。

## 发现的问题

P2.65a 后的实际普通模式页面仍有两套近乎相同的 Blob 下载代码（当前原始存档与异常重置前备份）。二者都在 `link.click()` 后安排 30 秒对象 URL 清理，异常分支则立即回收 URL。部分移动浏览器/WebView 对 Blob 下载的消费和计时器调度具有不确定性；若定时器调度抛错，原代码会在 catch 内**立刻回收已经请求下载的 URL**，从而增加下载失败风险。此外重复实现使两类备份的异常处理容易偏离。

## 同一主题的四项工程增量

1. **统一只读下载请求：** 新增 `merge/save-download.mjs`，接收现有 `prepareLocalSaveExport` / `prepareAbnormalResetBackupExport` 的准备结果。严格检查导出回执、Blob API、URL API 和 DOM 能力；仅创建 Blob、短暂插入 `<a download>` 并请求点击，不写入本地存档、不访问剧情存档、不发网络请求。
2. **移动端生命周期安全：** 将对象 URL 延迟清理窗口从 30 秒扩至 120 秒；若下载点击已发出但浏览器无法安排清理计时器，则保留 URL（单次原始导出上限仍为 2 MB），避免立即回收阻断潜在异步下载。该异常会返回 `cleanupDeferred:true`，提示用户核实文件是否存在。点击/Blob/URL 生成失败则立即尝试清理并报告失败。
3. **两种实际页面入口统一：** `main-locked.mjs` 的普通原始存档和异常重置前备份按钮共用上述下载协调器，保留对无数据、过大、编码失败、UTF-16 封装备份的既有说明。成功只表述“已请求下载”，**不宣称文件落盘成功**。
4. **专项回归：** 新增下载协调器单元测试与实际 HTML 入口 DOM 组合测试，验证原始字节、异常备份不被新存档替代、无存档写入、失败反馈、临时 URL 清理时序及计时器失败不提前回收。

## 验证和风险

本地可运行独立下载模块的 Node 单元测试，但由于当前执行容器无法 DNS 解析 GitHub，不能本地完整检出仓库并执行 `bash scripts/security-check.sh`；完整全仓库 Node 回归、安全脚本及完整 Git 历史密钥扫描必须以**本次最新提交 SHA** 对应的 GitHub Actions 三项均成功为准。新增 DOM 用例仍属于 Node 模拟浏览器行为，不等于真实 iPhone Safari、微信 WebView 或文件实际落盘测试。

下载成功回执只能证明脚本请求了锚点点击。浏览器可能忽略下载或交由系统处理，用户必须核实下载文件实际存在且可读取；尤其在异常重置前，不得仅凭提示推断备份完成。若计时器无法安排清理，最多可能暂时保留一个不超过 2 MB 的对象 URL，直到页面释放。

**边界：** 不修改 `main`、剧情分支、正式导航、部署白名单、经济参数、存档格式、在线 Supabase、云端代码或美术。提交以 `[CF-Pages-Skip]` 开头，PR #58/#59 保持 Open/Draft，不合并、不部署、不标记 RC。Cloudflare Pages 预览分支配置尚无法独立核实，GitHub 状态检查不是 Cloudflare 实际零部署证明。
