# P5：云屿首卷经济门槛审计（独立分支，未发布）

## 目的与范围

新增纯分析工具 `merge/story/economy-audit.mjs` 和专项 Node 测试，将“第一单→花园→港湾→门面”目前写入游戏的经营门槛，投影成可以重复执行的**乐观订单资源模型**，为后续实际玩家模拟与剧情节奏测试建立量化基线。

- 重用 `merge/economy.mjs` 的 `makeOrder`、`getLevel` 与 `BUILDINGS`，不用自造订单金币、经验值与升级规则。
- 委托始终维持 3 条活跃订单，完成后从真实 `nextOrderIndex` 和当时的 XP/门面状态生成新订单。对比先进先出和最省估算体力两种排单策略。
- 建筑顺序依据叙事：先花园（4级、160金币）、后港湾（6级、330金币）、再店面（2级、60金币）。每次真实扣除投影金币，记录订单数、累计 XP、金币余额和估算生产能量。
- 仅分析“已经可以交付订单”的奖励流，**不产生任何实际道具、金币、存档或在线请求**。源游戏没有接入此分析工具的导入或调用。

## 预期数量级（由模型得到，须以 CI 及脚本输出为准）

在无其他消费与奖励、无需等待获得目标材料的非常乐观前提下，两种订单选择方式均需约 15 单达到花园、约 38–40 单达到港湾与门面，累计生产体力需求约 190 点。超过初始 120 点的差额按每 3 分钟恢复 1 点换算，意味着被动恢复的**模型值**大致在 3.5–4 小时范围，但不是实际游玩时长或真正下界：初始材料、随机掉落、合并、免费补给、在线间歇、冷却、库存堆积等都会使结果偏离。

这些数字不能被用于承诺真实首卷通关耗时，也不能直接用来修改正式金币/经验奖励。要确认有没有卡关，下一阶段需要基于真实 7×8 棋盘、生产器分布、各种策略和随机种子的离线蒙特卡洛模拟，再做 iPhone/微信实机试玩。

## 当前得到的设计启示

第二章花园可能成为第一个明显的节奏跳变点：从第一单后可连续读故事，变为累计十余单才继续主线。港湾要求更高，需检查清晰的长期目标显示、可预测的体力节奏，以及是否允许支线与经营分段并行。不能只靠降低经济门槛掩盖玩法单调或目标不清。
