# 云屿百物铺 V3 · P2.61h 普通模式动作版本不变量（未发布）

## 问题与边界
未来普通模式页面将通过 `commitNormalActionWithLock` 执行玩家动作。此前事务会验证存档格式与写后原字节，但没有要求成功动作必须使 `revision` 恰好递增一次。错误的动作适配器可能以同一版本写入不同金币/棋盘，导致跨标签同版本经济冲突，也可能跳过版本号。此问题不能仅靠 Web Locks 解决。

## 最小修复
- 在锁内读取可信 V3 基线后，记录动作执行前的 `revision`。
- 成功动作必须返回不同于输入的状态对象，且新 `revision` 恰好等于原版本 + 1；否则返回 `ACTION_REVISION_INVALID`，不写入、不返回可发布状态。
- 保留原有同步动作、CAS、写后原字节核验和失败阻断逻辑；普通模式计时器不在此动作规则内，仍允许不递增版本的纯时间推进。
- 所有当前 V3 引擎成功玩家动作均单次递增版本；此检查仅约束未来的页面动作接入，不改变现有同步页面或经济参数。

## 专项验证
`node --test tests/merge-normal-action-transaction.test.mjs` 新增三项：同版本伪造金币、跳号版本、原位修改输入对象均必须拒绝且存档原字节不变。已有真实引擎动作测试继续验证正常单步版本与精确回读。全仓库回归、静态安全与部署隔离、完整 Git 历史密钥扫描以新提交 SHA 的 GitHub Actions 为准，不能用旧 SHA 结果代替。

## 未解决风险
此校验不是防作弊系统，不能防止恶意脚本构造合法版本的伪造状态；真正的经济权威必须由未来后端校验。当前 `merge/main.mjs` 仍使用同步 `persist()`，尚未完成所有启动、动作、计时器、重置的统一 Web Locks 接入。旧版未协调标签仍可能竞争写入；iPhone Safari、微信 WebView、真实跨标签与 PostgreSQL/Edge 尚未验收。
