# P148｜剧情工作台设备时间回拨的只读诊断（2026-10-30）

## 问题与边界
玩家在手机后台停留期间若手动回拨系统时钟，原本 180 秒体力恢复或 45 秒工坊冷却可能被显示成远超正常范围的等待时间，误导玩家认为卡死。首卷经营不能通过改时钟、重置或免费补给绕过资源规则。

## 本轮修复
- **体力**：当前时间早于存档中的 `energyAt` 且体力未满时，返回 `CLOCK_BEHIND_ENERGY`，建议核对设备日期和时间；不再展示误导性的超长自然恢复倒计时。
- **工坊**：所有生产器都处于冷却、最早剩余时间仍超过引擎规定的完整 `PRODUCER_RECHARGE_MS` 时，返回 `CLOCK_BEHIND_COOLDOWN`，提醒核对系统时间并保留原存档。
- 优先保留原有满盘解堵、订单交付、仓库扩容诊断。正常计时与正常冷却路径保持不变。
- 只读提示：不改 `advanceTime`、经济数值、存档协议、revision、Web Locks 或普通模式；不自动调整时钟、发放体力、扣除冷却卡或重写存档。

## 验证
`node --test tests/merge-story-resource-recovery.test.mjs`；新增两项针对时钟回拨的正反路径及引擎恢复测试，继续由仓库完整 Node、安全静态与历史密钥扫描三门禁验证。最终 SHA 与 CI 结果见 PR #59 本轮评论。

## 风险
这只能识别可推断的**回拨**异常，不能凭客户端时间判断用户是否主动快进、跨时区或系统校时；真实 iPhone Safari、微信 WebView 后台冻结与时间跳变仍待实机验证。localStorage 跨标签写入不是原子事务，原有保护边界不变。未授权发布。
