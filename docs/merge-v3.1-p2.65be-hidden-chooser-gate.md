# P2.65be · 普通模式原生文件选择器后台生命周期收口（2026-10-29）

## 问题与修复

普通模式的文件选择器在 iOS Safari / 微信 WebView 中可能导致页面暂时隐藏；文件 change 事件也可能在页面仍隐藏时到达。现有导入流程已将隐藏期间的文件选择排队，回到前台后才允许重新核验原始存档与确认恢复。**本轮不放宽任何存档原始字节、Web Locks 或显式确认门禁。**

定位到一个可见状态不一致：用户开启导入选择器后，页面经历**第二次**后台切换，代码会撤销旧的 `importPicker`，但未立即刷新“取消导入等待”按钮的显示状态。按钮可能仍可见，尽管旧选择器已失效。修复在后台生命周期处理结束时调用现有的 `refreshImportCancel()`，仅同步界面，不修改存档、恢复前备份、引擎经济或锁协议。

## 新增真实 Chromium 验证

1. 原生选择器弹窗由测试替身代替，真实标签页的 `document.hidden`、`visibilitychange`、`File`、`DataTransfer`、页面导入事件及 `localStorage` 仍由 Chromium 执行。标签隐藏期间派发文件 change，断言隐藏时没有恢复确认、没有覆盖原始存档/恢复前备份；前台核验后拒绝或由用户主动取消，最终保留原始字节。
2. 选择器未结束时经历两次后台切换，断言第二次隐藏立即撤销旧选择器的取消等待 UI；之后迟到的 change 必须被拒绝，不触发恢复确认，不改写存档/备份。
3. 原有双标签、Web Locks、BFCache、真实文件下载、重置/恢复及移动端 CDP 触控回归保持原断言，不允许用无界重试替代失败。
