# P111 · 剧情与经营依赖刷新重入保护（未发布）

## 发现与修复

剧情页读取工作台存档、工作台页读取剧情存档时，如果读取过程中同步发生对应的跨标签 StorageEvent，事件处理器会重新执行 render()。旧 render() 返回后继续渲染，可能把新一轮已确认的经营门槛、建筑前置条件覆盖成旧状态。此前的单次快照一致性测试未覆盖这一重入时序。

两处入口现在为每次渲染分配递增 generation；依赖存档读取返回后，如果发现更晚一轮渲染已开始，旧渲染立即退出，不再覆盖新 DOM。此修复仅影响只读渲染，不更改存档格式、经济、剧情顺序、原始字节 CAS、Web Locks 或生产部署。

## 回归与限制

P111 在真实入口模块的 Node DOM 故障注入中覆盖两个方向：剧情存档在工作台 render() 读取时触发嵌套刷新，以及工作台存档在剧情 render() 读取时触发嵌套刷新。确认新一轮门槛提示保留、没有新增写入、普通模式存档未受影响。全仓库 Node、安全静态与全历史密钥扫描以该 SHA 的 GitHub Actions 实际结果为准。

本测试不是 Safari、微信 WebView 或真实双标签的模拟器；浏览器 StorageEvent 的实际调度通常是异步的，此处故意注入最不利的同步重入。localStorage 仍不具备跨标签原子事务，真实四章离线通关、BFCache、确认框和文件下载落盘仍须实机验收。PR #59 保持 Draft；禁止 main 合并、发布、线上数据库和部署配置修改。
