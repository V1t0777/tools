# 《云屿百物铺》V3 · P2.31 跨标签未来时钟保护（未发布）

## 问题

P2.30 已根据 `energyAt` 的时间差校验体力恢复预算，但没有检查远端的新增恢复时间戳是否晚于当前设备时间。跨标签同步时，如果另一页面提交同修订号、未来时间戳与对应增加的体力，旧策略可能误判为合法恢复；在生产器到期时也可能把异常前移的 `energyAt` 一并接受。

## 本轮单点修复

- `merge/storage-event-policy.mjs`：当远端 `energyAt` 相对本地基线发生变化时，必须满足 `remote.energyAt <= now`，否则拒绝跨标签采用，原 UI 会暂停保存并提示备份核对。
- 保留“设备时钟回拨后，原始基线已在未来但时钟字段未变”的可比较性，避免对完全相同的原始状态误判冲突。
- `tests/merge-storage-event-policy.test.mjs`：新增未来体力恢复、生产器冷却到期但恢复时间戳超前、正常到期和原始基线未变的专项断言。
- 不调整存档格式、经济规则、部署配置或剧情存档键；不新增网络、数据库或账号功能。

## 验证与剩余风险

须核查本次 HEAD 的全仓库游戏/安全回归、静态安全/部署隔离、完整 Git 历史密钥扫描三项 CI，三项未全部成功不得标记完成。此检查依赖设备 `Date.now()`，系统时钟被人为修改或多个设备时钟不一致时可能保守拒绝同步，不能替代 Web Locks 的事务保证。现有普通模式同步 `localStorage` 仍存在同时写入的竞争窗口，真实双标签浏览器、iPhone Safari 和微信 WebView 尚未验收。
