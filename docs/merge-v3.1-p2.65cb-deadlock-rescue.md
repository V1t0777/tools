# P2.65cb｜普通模式可达死局的最小解围修复（未发布）

2026-10-30。承接 P2.65ca：真实合法操作可到达 56/56 棋盘、4/4 仓库、无可交订单、无合成对子、金币不足的规则级死局。此问题阻止 RC。

## 本轮变更
- 新增纯引擎操作 `discardDeadlockedMaterial`：仅当只读诊断为 `hard-deadlock`、目标仍为同一件原料、调用方明确 `confirmed:true` 时，删除**一件**选中原料、revision +1；不奖励金币、经验、体力、道具或仓库格数。
- 普通模式新增「死局解围：弃置选中原料」按钮。正常可交单/合成/收纳/扩容时禁用；仅真实死局且已选中原料时可用。操作前以原生确认框说明永久损失并建议先导出备份。
- 触控授权绑定渲染代次；确认绑定原始字节、选中原料 ID、导入 epoch 和页面生命周期。确认后再次核验；真正写入经过现有 `runtime.action` 的 Web Locks、revision/CAS、原始字节检查，取锁后引擎再次诊断。
- 整理提示更新为人工解围指引。存档 schema、云存档、经济数值、正式导航及剧情源文件不变。

## 验证要求与残余风险
- 从初始存档通过真实合法操作到达死局，再确认弃置一件原料并恢复生产；未确认、旧 ID、重复确认不得写入。
- 双标签同锁：第一标签解围恰好一次写入，第二标签旧基线拒绝；剧情存档、恢复前备份和异常备份原始字节不变。
- 存在正常合成路径时禁止弃置；按钮默认禁用，必须确认并绑定快照。
- 全仓库 Node、`security-check.sh`/部署隔离、完整历史密钥扫描须以**新 SHA**实际 CI 为准。Chromium 测试不等于 iPhone Safari 或微信真机验收。
- 这是玩家主动承担原料损失的最后解围方式，不是自动清盘、免费资源或作弊后门。诊断器未来规则变化须同步回归。
- PR #58/#59 保持 Open/Draft；不合并 main、不发布 Pages/Cloudflare/Edge、不执行 Supabase SQL/迁移、不更改正式导航和部署白名单。Cloudflare 后台实际部署状态不可核实时持续保留风险。
