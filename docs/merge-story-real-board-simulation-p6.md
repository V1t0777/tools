# P6 · 首卷真实合成棋盘经济回归（未发布）

## 本轮目标

将 P5 的“订单立即可交付”乐观投影推进为**真实 V3 引擎驱动的离线、可复现模拟**。代码位于 `merge/story/board-simulation.mjs`，专项测试位于 `tests/merge-story-board-simulation.test.mjs`。模块不导入浏览器存储、网络 API、剧情进度写入器，也不产生金币/道具奖励。

### 实际使用的玩法机制

- 通过 `createInitialState` 初始化真实 **7×8** 棋盘、初始材料、三个生产器和三个订单。
- 所有生成、合成、交付、建设均调用 `produce`、`moveOrMerge`、`fulfillOrder`、`upgradeBuilding`，并逐步用 `validateSave` 检查存档不变量。
- 掉落使用可复现的 32 位 LCG 种子。生产器 12 次充能、45 秒冷却及 120 体力、每 3 分钟 1 点自然恢复，均由原引擎决定。
- 固定的自动策略：先交付棋盘上已满足的订单，再合成未超过当前订单上限的相同材料，最后为当前最低阶未完成订单生产。按“花园→港湾→门面”顺序支付真实建筑成本。
- **叙事前置条件仅在模拟中假定已阅读**，并未模拟真实剧情页面、用户手势或跨页面存档。现实 UI 中仍须完成相应剧情才能点击建设。

### 解读边界

该自动玩家非常高效，且假定点击、阅读、整理操作耗时为零；报告的 `elapsedMinutes` 只统计由于工坊冷却或体力不足造成的被动等待，不是用户通关耗时。它只使用一套贪心策略，未使用仓库、升级、补给商店和一次性道具；并不能代表普通玩家、长尾随机数、真实 iPhone 帧率或存档并发问题。

本轮实测初步样本（最终以 SHA 对应的 CI 输出为准）：
- 种子 42：**40 单、103 次生产、71 次合成**；花园在第 15 单，港湾与门面在第 40 单。仅计自动策略的强制等待约 4.5 分钟。
- 初始棋盘已有一件可以完成的二阶订单，因此第一单可以不消耗额外生产体力。
- 64 个固定随机种子在该高效策略下均到达第三个建筑门槛，生产次数范围 **98–117**、合成 **65–85** 次、自动策略强制等待 **3–6 分钟**（CI #40060926223 初次运行结果；最终应核对更新后的 SHA）。
- P5 的约 190 点生产体力来自启发式估算，**不是**真实棋盘耗能下界。两者存在明显偏差，不应据 P5 的 3.5–4 小时被动恢复估计直接调参。

### 研发结论与后续

真实引擎基线可以验证一种高效策略的可达性，却不能证明普通玩家不会卡关。下一步增加保守/新手/仓库策略与高压力种子、棋盘拥堵统计，再据此决定是否改订单难度、教程引导或 UI 提示；随后安排 iPhone/微信真机体验。
