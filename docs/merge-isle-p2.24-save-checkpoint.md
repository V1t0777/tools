# 《云屿百物铺》V3 · P2.24 异步保存期间的新进度保留（未发布）

## 本轮工程增量

新增 `merge/save-checkpoint.mjs`：`createNormalSaveCheckpoint(storage, lockManager, {expectedRaw})`。这是未接入玩家界面的普通模式存档状态适配器，用于解决 P2.23 单飞保存期间又发生玩家操作时，较早一次写入成功却错误显示“所有进度均已保存”的问题。

- `stage(state)` 在调用当下校验并序列化一份独立快照，防止调用方之后修改对象影响已排队/执行中的保存；拒绝无效或超出存档上限的状态，不覆盖已有合法待保存快照。
- `flush()` 使用 P2.23 单飞及 P2.22 Web Lock 保存，只在确实收到 `SAVE_VERIFIED` 和读回成功时推进内部原始存档基线。写入期间若再次 `stage()`，返回 `NEWER_STATE_UNSAVED`，保留较新快照及 `dirty=true`；**绝不自动排队或重试**，需调用方在适当时机显式保存。
- 旧标签改写、存储结果不确定或写入后读回不符会进入 `blocked` 状态；此后拒绝写入直到重新读取并人工协调。仍允许内存中更新待保存快照，但不能将其标记为已持久化。
- 缺失可信基线、不支持 Web Locks、锁繁忙均不降级为无锁写入。返回值不包含金币、背包或原始存档文本。
- 仅用于**普通日常保存**，不实现确认重置或文件恢复；二者必须继续遵守各自的明确授权和原始备份流程。

## 专项回归

`tests/merge-save-checkpoint.test.mjs` 覆盖：正常保存及基线推进、异步期间新进度、调用方对象后续修改、非法状态保留旧快照、跨标签过期基线、锁不支持、缺失可信基线、提交后异常及剧情模式隔离。

## 边界与后续工作

本轮没有接入 `merge/main.mjs`，所以正式游戏的 `persist()`、体力自动恢复、确认重置、启动迁移仍是旧同步路径。**该模块不等于玩家页面已经安全使用异步存档。** 下一轮应先核查所有同步入口和浏览器兼容策略，确保 UI 能在失败时显示未保存状态，避免继续接受可能无法持久化的关键操作；之后才可逐步接线。

`localStorage` 不支持原子 CAS，旧标签及未参与同名 Web Lock 的路径仍可能竞态。没有完成真实双标签、iPhone Safari、微信 WebView、断电故障或云端验收。没有运行线上数据库/迁移，没有部署或发布；PR #58 保持 Open/Draft。必须以本次 HEAD SHA 的三项 GitHub Actions 全部通过作为工程检查门禁，CI 不能替代实机测试。
