# 《云屿百物铺》V3 · P2.58 后台计时器暂停与恢复前存档核验（未发布）

## 问题
普通模式目前仍由 `merge/main.mjs` 的同步 `persist()` 写入，P2.45–P2.57 的独占 Web Locks 模块尚未完整接入。即使浏览器页面进入后台，定时器仍可能运行、恢复体力并写入 `localStorage`，与正在前台游玩的另一个标签竞争；Safari 等移动浏览器还可能延后派发 `storage` 事件，导致后台标签恢复时持有过期基线。

## 单一安全增量
仅在当前页面 `merge/main.mjs` 做两处受控变更：
1. 计时器回调发现 `document.hidden` 就直接返回，后台不计算或保存体力/冷却，也不进行无意义 DOM 更新。计时进度没有丢失：再次前台显示且存档未变化时，下一次秒级 tick 按实际经过时间补算。
2. `visibilitychange` 从后台恢复为可见时，通过既有的只读 `peekLocalV3()` 重新校验存档原始字节。若存档缺失、损坏、或与本标签最后确认的 `persistedRaw` 不同，则取消旧拖拽/选择并设置 `saveIssue`，明确暂停写入；不自动合并、覆盖或迁移存档。
3. 保留此前后台隐藏时取消拖拽、迟到点击拦截和原有 `storage` 事件跨标签同步逻辑。导出原始备份和用户主动确认重置入口不改变。

本轮**不引入部分持锁写入**，因此不会发生某些入口已改 Web Locks 而其余入口继续无锁的混合接入。改变的是现有同步页面在后台时的写入行为。

## 专项回归与验收边界
`node --test tests/merge-background-resume-guard.test.mjs` 覆盖后台计时器零持久化、恢复时原始字节一致、恢复时版本变化、删除/损坏存档、陈旧拖拽取消与原有后台手势取消。按 `AGENTS.md` 仍须 `bash scripts/security-check.sh`；最新 HEAD 的全仓库游戏与安全回归、静态安全与部署隔离、完整 Git 历史密钥扫描都成功后才可宣称工程验证完成。

**限制：** 仅降低移动端后台写入与丢失事件带来的竞争风险，不能为不同标签之间的所有同步 `localStorage` 写入提供跨标签原子性。实际页面统一 Web Locks 接入、Safari/微信 WebView 实测及浏览器下载/恢复验收仍未完成；不以模拟测试替代真实设备/数据库验收。
