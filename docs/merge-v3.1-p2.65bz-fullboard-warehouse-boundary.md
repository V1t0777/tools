# 云屿 V3.1｜P2.65bz：满盘与满仓组合边界核验（未发布）

## 发行阻塞发现

上一轮 12 组低效率、60 天模拟均未出现满盘停顿，但这不能证明所有合法存档不会卡死。本轮构造**通过正式 `validateSave` 的对抗性快照**，并调用真实引擎操作，验证“56 格全满、仓库全满、没有匹配委托、没有低于最高阶的可合成对子、金币不足以扩容”的边界。

结论：该快照下，交单、合成、收纳、取出、生产、仓库扩容均不能腾出空间，`diagnoseBoard` 返回 `hard-deadlock`。等待体力恢复、工坊冷却结束仍无法解围。**这属于已确认的规则级 P0 风险，不得因自动化测试通过而标记发行阻塞清零。** 这些快照是合法结构的故障注入，**尚未证明玩家能够仅靠正常操作到达该精确局面**；需继续做可达性搜索和正常游玩路径复现。

## 真实规则恢复路径与边界

- 仓库有一个空位：玩家可手动收纳，再合法生产；无资源凭空增减。
- 仓库满、棋盘满：仅当玩家实际达到升级等级并有足够金币，才可扩容、收纳。
- 仓库已满级（8 格）：即使金币充足，也不能通过不存在的升级逃生。
- 现有委托恰好可交、或存在合法合成对子：均能释放棋盘一格。
- 工坊充能与体力恢复只解决生产资源不足，不会清空满棋盘。
