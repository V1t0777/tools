# 云屿 V3.1 P2.65x｜Blob URL 撤销失败的资源额度保护（2026-10-28）

## P0 问题与范围

P2.65u 已限制同时保留的临时下载 URL 为 8 个，但下载按钮点击失败、来源二次校验拒绝或 DOM 操作异常时，原实现先删除额度记录，再尽力撤销 Blob URL。如果 WebView 的 `revokeObjectURL` 同时抛错，已分配 URL 会失去跟踪；反复失败可能持续占用内存。另有到期撤销偶发失败、同步触发定时器造成清理机会丢失的问题。

## 本轮实现

- 原生下载未发起时，先尝试撤销临时 URL；**仅撤销成功才释放额度**。撤销失败继续计入 8 个上限，并安排一次延迟清理；后续显式下载仍可按到期时间重试。
- 下载已发起、到期撤销临时失败时，追加一次有界重试；始终不提前撤销年轻 URL。
- 定时器同步回调发生在清理逻辑正式启用之前时，重新安排一次清理，不使用无限重试或递归循环。
- 所有变化局限于只读浏览器下载辅助模块；不触碰存档字节、剧情命名空间、经济逻辑、云端、正式导航或部署配置。

## 验证与风险

- 本地 Node 专项三项：连续失败撤销不得突破 URL 额度、到期撤销失败后重试、同步定时器回调后重新清理。
- 提交后须核实新 HEAD 的全仓库 Node、`bash scripts/security-check.sh` / 部署隔离、全 Git 历史密钥扫描，未完成不得宣称发行门禁通过。
- 浏览器若持续拒绝撤销，模块会保守占用额度并提示稍后再试；这优于释放额度后继续无限分配 URL。浏览器计时器完全冻结时只能在下一次用户显式下载时补偿清理。
- 下载成功仍仅表示发起原生点击，**不代表 iPhone Safari 或微信 WebView 已实际保存文件**。真实双标签、BFCache 和手机落盘验收仍为发行阻塞。
