# 云屿 V3.1 · P2.65u 离线下载临时链接时序与额度保护（2026-10-28）

## P0 范围与发现

普通经营模式导出及两种恢复前备份共用 `requestBrowserSaveDownload`。旧实现只防止**同步**异常计时器过早撤销 URL；若 WebView 异步提前触发清理回调，可能在文件尚未交给下载管理器前撤销 Blob URL。另一个边界是 `a.click()` 的同步重入：旧实现点击返回后才登记临时链接，嵌套下载可以绕过最多 8 个链接的上限。

## 修复与验证设计

- `merge/save-download.mjs`：定时清理时重新核对到期时间，提前回调最多再安排一次剩余期限；仍提前则等待下一次用户主动下载时的过期清理。不会为尽快释放额度而提前撤销。时间戳溢出直接拒绝。
- 在 Blob 创建及 `a.click()` 前预留额度，嵌套下载也计算外层请求；点击/URL/Blob 失败立即释放预留并尽力撤销已创建的 URL。单页每 URL API 最多 8 个待清理下载。
- `tests/merge-save-download.test.mjs`：更新正常到期测试，新增提前异步计时器、重入下载额度、失败释放与溢出时钟三项专项回归。先以 V8 隔离环境对修改后的真实函数执行四组定向故障注入；最终全仓库 Node、安全及完整历史扫描以**新 SHA 的 Actions**为准。

## 发行边界与未消除风险

返回 `ok:true` 仅表示浏览器锚点点击已发起，**不证明文件已落盘**。浏览器计时器完全冻结、撤销 API 拒绝、时钟异常时，链接可能占用额度直至下次下载/刷新；宁可限制下载，也不提前撤销可能仍被使用的文件。真实 iPhone Safari、微信 WebView、双标签和“文件”落盘/字节校验仍须实测。无经济、存档写入、剧情源文件、云服务、main、导航或部署配置改动；PR #58/#59 保持 Open/Draft，不发布、不操作线上 Supabase。Cloudflare 后台部署状态仍须独立核实。

## CI 夹具修订

首次提交 `a9dda09` 的 Node 回归 1092/1093：旧 `merge-save-download-limits.test.mjs` 在虚拟时钟仍为 1000ms 时立即调用到期回调，却要求立即撤销，与新的防提前撤销安全约束相矛盾。现将测试时钟先推进完整 120 秒，再执行该回调；保留额度恢复和 URL 撤销的原断言，新增的提前回调测试继续单独覆盖安全行为。以本次修订 SHA 的完整 Actions 三项门禁为准，不沿用失败 SHA。

第二次 CI 仍有一项旧测试断言未考虑正常到期后的批量过期清理：定时器先回收首个 URL，下一次下载按既有机制回收其余 7 个过期 URL。修订为分别核对首个定时回收与完整过期批量回收，未修改业务逻辑或降低安全断言。最终验证只以新提交 SHA 为准。
