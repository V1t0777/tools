# 《云屿百物铺》V3 · P2.47 计时器独占写入边界（未接入页面、未发布）

## 目的与范围
P2.46 为用户主动触发的普通模式动作提供 Web Locks + 原始字节基线复核 + 写后精确读回，但 `merge/main.mjs` 的每秒 `advanceTime()` 仍独立经由同步 `persist()` 写入，若先接入点击动作而遗漏计时器，仍会留下无锁写入者。

本轮在 **同一** `merge/normal-action-transaction.mjs` 内新增 `commitNormalClockWithLock()`，不增加另一把锁、不引入本地存储自旋锁，不改现有页面及存档格式。其调用时必须给出已确认的原始存档字节 `expectedRaw` 以及有效时间戳。

## 事务约束
1. 缺少可信基线、非法时钟、浏览器无 Web Locks 或锁忙，均在写入前拒绝。
2. 独占锁内重新读取并校验真实 V3 存档，原始字节不符即拒绝。
3. 调用实际引擎 `advanceTime()`；若体力和冷却没有变化，返回 `CLOCK_UNCHANGED` 并**零写入**，避免每秒无意义刷盘。此结果是当前存档的已验证读取，不是写后读回。
4. 只有状态变化才使用 `commitNormalSnapshot()`，写入及精确读回成功后才暴露新状态；失败不发布更新状态。
5. 同一时刻旧标签的基线可能已被新标签更新，拒绝自动合并。无锁写入者仍可能破坏跨标签原子性；必须全部迁移后才可声称端到端保护。

## 仍需解决的入口（下一轮重点）
- `loadLocal()` 可能在模块加载时执行 V1/V2 备份与迁移；`prepareNormalStartup()` 也可能保存首次存档或时间推进。需整体移入同名持锁启动流程。
- `merge/main.mjs` 的主动游戏动作、每秒计时器及确认重置目前仍经同步 `persist()`；异常重置备份键也必须持相同锁。
- 页面需要异步 busy 状态、手势撤销、保存前重读和失败安全暂停，防止连续点击复用过期状态。
- 普通模式与剧情模式存档命名空间不得混用，云存档不在本轮范围。

## 验证边界
`node --test tests/merge-normal-clock-transaction.test.mjs` 涵盖无变化零写入、真实引擎体力恢复、旧基线、锁忙、无锁支持、异常时钟、损坏存档和写后读回失败。提交之后以**该 HEAD** 的全仓库回归、静态安全与部署隔离、完整 Git 历史密钥扫描为准。单元模拟不等于真实双标签、iPhone Safari、微信 WebView 或线上数据库验收。
