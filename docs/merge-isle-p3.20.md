# 《云屿百物铺》P3.20 — 一次性 PostgreSQL 预验收隔离加固（未发布）

> 仅适用于 Draft PR #58 的研发验证，不部署、不操作线上数据库、不改正式导航或美术素材。

## 背景

P3.17 的本地预验收只依赖数据库名称和一个测试表是否存在来判断隔离环境，无法排除同一数据库中已有其他业务对象；自动创建数据库角色还可能改变共享集群的全局角色配置。

## 本次修改

- 在任何测试写入之前，通过只读查询验证数据库实际连接地址、数据库名称与所有者。
- 验证数据库确实为空：不允许已有自定义模式、公开模式中的表、函数、类型、非默认扩展、外部服务器、发布或事件触发器。
- 三个测试角色必须由操作者事先在**全新一次性 PostgreSQL 集群**内准备，且不能登录。预验收脚本不再创建集群级角色。
- 严格检查本地连接参数，阻断直接调用脚本函数时的异常连接选项。
- 检查失败时停止，不执行数据库写入或并发压力测试。

## 测试

新增三项 Node 回归：隔离目标指纹验证、异常连接参数拒绝、先校验后写入的源码结构约束。仍需完整 Node 自动化测试、静态安全与部署隔离检查，以及 Git 历史敏感内容扫描全部通过。

## 未解决的限制

本轮没有创建 PostgreSQL 实例，也没有执行真实数据库并发、权限或 RLS 测试。读检查和随后写入之间仍存在时间差，因此该脚本只允许在没有其他客户端的全新、可销毁的本机集群中执行，绝不能用于现有 Supabase 项目。Edge 网络、iPhone Safari 和微信 WebView 仍需单独验证。
