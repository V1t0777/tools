# 云屿 V3.1｜P2.65ca：正常操作路径满盘卡局可达性审计（禁止发布）

## 本轮目的

继 P2.65bz 的结构合法但未证明可达的极端存档后，增加 **从 createInitialState 开始、仅使用正式引擎公开合法动作** 的确定性重放测试，检验是否可能进入 56 格棋盘与仓库均满、无可交订单、无可合成对子、无可支付扩容的规则级死局。

## 可重放策略

1. 新建普通模式存档；合法地将现有烘焙材料 3 件、花艺材料 1 件收入四格仓库。
2. 将初始两次茶饮合成正常执行，不交付任何订单，不修改订单、金币、经验、棋盘、仓库或存档字段。
3. 每轮优先执行真实 moveOrMerge；否则执行真实 produce（工坊位置固定来自初始状态）。虚拟时间单调前进，按正式 advanceTime / 冷却与体力规则运行。
4. 接近满盘时，若仍有茶饮二阶材料，则生产其配对材料并合法合成；否则以未使用过的烘焙工坊产出一阶材料填入最后空位。全部随机值固定为可重放的合法区间值。
5. 每次成功操作后调用正式 validateSave；终局以 diagnoseBoard 和所有相关失败动作/存档字节不变为证据，日志打印动作数量、最终资源与最后操作序列。

新增 `tests/merge-normal-reachable-deadlock-p0.test.mjs`。测试必须通过最新 SHA 的实际 Node / 安全 / 历史扫描 CI 才能认定可达性证据有效。此用例是**对抗性但合法的玩家行为**，不等于真实玩家频率或经济平衡统计。

## 发行判断

若上述可达性用例通过，P0 将从“结构合法风险”升级为“正式操作可达的真实规则级死局”；**不得宣布经济 P0 已解决，不得进入 RC**。修复方向必须由可验证的最小玩家主动解围机制与守恒回归决定，不能偷偷清盘、免费奖励、作弊或修改存档以掩盖问题。

继续保留 iPhone Safari / 微信 WebView 真机文件选择与下载落盘、跨标签/BFCache、普通/剧情存档隔离、PR #59 集成及 Cloudflare 实际部署状态风险。所有提交 [CF-Pages-Skip]，PR #58/#59 Open/Draft；不改 main/导航/白名单/线上 Supabase，不合并、不部署、不发布。
