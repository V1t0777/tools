# 云屿剧情 P90｜双损坏存档的独立恢复与上游单调下载时钟（2026-10-28）

## 发行阻塞背景
剧情对白和剧情经营工作台使用不同本地键，普通模式使用第三个键。两份剧情存档可能同时损坏；只恢复其中一份时，不能静默清理另一份、覆盖普通模式或继续使用恢复前的下载证据。移动 WebView 的系统时间前跳亦不应提前撤销尚在使用的 Blob URL。

## 本轮安全同步
上游 PR #58 的 P2.65y 只修改 `merge/save-download.mjs`，新增其专项测试及文档。同步前核对共同祖先 `69e36f8`：剧情分支该模块 Blob SHA 与共同祖先相同（`2c931b35`），新增路径不存在；以双父合并保留双方历史，不强推、不触碰正常经营其他源码。下载模块优先使用单调时钟，仍保留旧浏览器回退和 8 个 URL 额度上限。

## 本轮剧情组合回归
新增 `tests/merge-story-dual-corrupt-recovery-p90.test.mjs` 四项专项场景：
1. 两份剧情键同时损坏，均需独立确认才能导出可逆 UTF-16 证据，禁止静默修复。
2. 明确确认恢复经营工作台后，对白损坏证据仍可导出；旧工作台证据失效；对白再次单独恢复，普通模式不变。
3. 等待 Web Lock 时，非参与标签页替换经营快照；旧确认不得重置新快照。
4. 浏览器存储写入被拒绝时，两个恢复入口均不得报告成功，也不得丢失原始字节。

## 验证与残余风险
新 SHA 必须完成全仓库 Node、静态安全/部署隔离、完整 Git 历史密钥扫描三项门禁；不能把历史 SHA 的 CI 视为新提交通过。此测试为 Node 模拟，不能证明真实 iPhone Safari/微信 WebView 的下载文件已经落盘，也不能把 localStorage 读写当成跨标签原子事务。仍需真实设备验证 BFCache、原生确认、离线四章通关、双标签竞态和异常证据保存。
