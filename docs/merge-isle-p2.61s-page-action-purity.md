# P2.61s 普通模式实际页面动作输入不可变保护

## 范围与原因

此前 P2.61r 只校验成功动作返回的新对象与 revision。若某个引擎动作先原位修改棋盘、金币或体力，再返回失败、成功甚至抛出异常，当前页面可能继续保留已污染的内存状态；后续计时器有机会将其持久化。

本轮仅修改 `merge/main.mjs` 的延迟求值动作入口：在执行函数式动作前序列化可信内存基线，执行后再次序列化比较。发现任何输入原位变化（包括循环引用导致无法序列化），立即阻断写入，使用动作前快照恢复内存、清除选中格和引导，并展示中文安全提示。同步动作抛出异常也不会穿透事件回调；未修改原始 localStorage。合法动作、正常失败动作保持原有行为。

## 专项回归

`tests/merge-page-action-purity.test.mjs` 通过 Node VM 执行实际页面 `commit(result)`：覆盖成功动作嵌套棋盘污染、失败动作金币污染、抛错后体力污染、循环引用及正常成功/失败路径。全仓库回归、静态安全与部署隔离、完整 Git 历史密钥扫描必须以**本提交 HEAD** 的 GitHub Actions 结果为准。

## 未解决风险

该保护不是跨标签原子性；仍未把启动迁移、计时器、重置与玩家动作全部接入同一 Web Locks。每次玩家动作会增加两次内存 JSON 序列化，尚未在真实移动设备测量开销。若引擎动作有外部副作用，本保护只能阻断本地状态发布而不能撤销副作用。同步页面仍不允许异步动作，Promise 返回路径后续需独立审查。iPhone Safari、微信 WebView、真实跨标签和 PostgreSQL/Edge 均未验收。

保持 PR Open/Draft；不合并 main、不修改部署白名单、不发布、不执行线上 SQL/迁移、不制作美术或作弊后门。
