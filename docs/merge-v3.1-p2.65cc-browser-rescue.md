# P2.65cc｜普通经营模式死局解围真实浏览器闭环（未发布）

日期：2026-10-30。承接 P2.65ca（合法操作可达死局）及 P2.65cb（最小确认弃置机制）。本轮仅补充独立真实 Chromium 页面专项回归，不修改经济规则、存档 schema、剧情源文件或正式部署配置。

## 本轮新增发行门禁

- 在真实普通模式页面加载通过 schema 校验的满盘满仓存档；独立的 P2.65ca 合法操作见证已证明该类状态可达。该浏览器专项使用合法结构的快速夹具，不冒充 2700 多次点击的真实 UI 重放。
- 未选择时弃置按钮默认禁用；选中原料后启用。拒绝确认不改变存档原始字节；接受确认只移除一件指定原料，revision +1，不增加金币、经验、体力、订单、仓库物品。
- 已完成弃置后，旧按钮点击不能再次提交；剧情存档、恢复前备份及异常重置备份保持原始字节不变。
- 触摸开始后取消并改选另一件原料：旧触控点击不得触发确认或写入；重新触摸才可对新选中原料执行一次确认弃置。
- 使用 Chromium 真实历史导航与 pageshow.persisted===true 验证 BFCache：离开前触控不得在恢复后执行；恢复后新触控可完成一次弃置。
- 仅通过真实 Chromium CDP、原生 localStorage、Web Locks 和普通页面运行时；PointerEvent 触控时序和 window.confirm 由测试注入，**不代表真实 iPhone Safari / 微信 WebView**。

## 验证与风险

CI 必须以本次新 HEAD 的全仓库 Node 回归、security-check.sh/部署隔离、完整 Git 历史密钥扫描三项实际结果为准；若任何一项失败，本轮不得标记验证完成。Chrome 在资源紧张的 CI 中仍可能超时，不能通过取消断言伪造通过。

保留 11/10 前 iPhone Safari、微信文件导入导出、实际 BFCache 和触控验收；剧情 PR #59 接口集成与 Cloudflare 后台实际部署状态仍为单独风险。PR #58/#59 必须保持 Open/Draft；禁止合并 main、发布 Pages/Cloudflare/Edge、执行线上 Supabase SQL/迁移或改正式导航/白名单。

首轮新 SHA 的 Node 回归曾因新增测试服务器在 404 资源请求中先发送 200 响应头、读取失败后又写入 404 响应头而失败（1223/1224）。已修复为先读取文件再写入响应头；以修复后的新 SHA 全套 CI 为最终依据，不将失败轮次计作通过。

第二轮 CI 的 Chromium 回归中，BFCache 恢复后页面按设计清除了旧选中原料，测试却直接点击需要选中原料才能启用的按钮，导致等待超时。现已先在恢复页面重新选中同一原料，再注入旧触控点击，验证其因租约过期而被拒绝，而不是依赖按钮禁用。随后用新触控确认实际弃置。最终结果仍以新 SHA CI 为准。

第三轮 CI 仍在 BFCache 恢复后新触控写入阶段超时；原生浏览器的拒绝确认、成功确认、选择变化防旧触控均已通过。为避免猜测根因，本轮添加仅失败时输出的非敏感状态快照（revision、按钮启用、选中格、提示与确认次数），不输出存档原文或备份内容，也不放宽断言。

失败快照显示 BFCache 后选中格与按钮已恢复、存档 revision=0，但新触控确认计数仍为 0，说明事件在确认之前被拒绝。新增真实 Target.activateTarget / Page.bringToFront 与即时非敏感提示采样，以区分页面生命周期悬挂和触控租约拒绝；不降低安全判断。
