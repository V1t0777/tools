# 云屿百物铺 · 私有四账号云存档研发验收矩阵（未部署）

## 本批次源代码
- 普通 V3：IndexedDB 全五键原子事务（主档、V1/V2 迁移备份、异常重置备份、恢复备份），真实 Chromium 56 格经营、跨标签 CAS、强制事务回滚、备份+恢复、无 Web Locks 页面验收。已更新原生 Web Locks 页面的迁移标记检查，旧标签不得跨迁移继续写本地旧档。
- 经营云端：已验证工具箱 Auth UID，四账号服务端白名单、HTTP 重试、Web Locks 持久 journal、服务端 CAS/幂等/经济审计；补给使用、购买、死局弃置已接入服务器经营指令。
- 剧情云端：独立未应用 SQL 和 Edge 草稿；剧情进度与工作台快照组成同一服务器 CAS 记录，与普通经济隔离；IndexedDB 持久化待发操作编号，收到不确定确认后必须原 UUID 重试；本地恢复仅在剧情 IndexedDB 事务中两个键一起提交/回滚。
- 开发版真实入口：\`merge/cloud-preview.html\`；仅当服务端已安全部署后才可与真实 Supabase 通信。提供现有工具箱登录、普通经营棋盘、订单、升级、补给、库存和手动剧情上传/下载/恢复操作。链接只存在开发分支，正式部署 allowlist 不包含它。

## 不能被省略的交付门禁
1. 现有 Supabase SQL 与 Edge **没有被部署**。严禁将本地模拟服务端的 Chromium 通过视为生产云端已可用。不得在生产库直接执行这些草稿。
2. 普通模式的旧本地钱包不可直接导入服务端权威经济。四个账号如需保留旧经营进度，必须有独立的管理员审阅、存档哈希和一次性授权迁移方案；否则只能选择全新服务器初始档。
3. 剧情工作台属于与普通经营隔离的非竞争单机经济快照，可用于私人跨设备备份，但服务器不能因此发放普通经营奖励。
4. 云队列在无 Web Locks 的浏览器仍阻断：剧情操作编号通过单独 IDB Journal 安全记录，但普通经营云 journal 的 IDB 同步适配仍要单独实现并做竞态测试。
5. 需要真实独立 PostgreSQL 的 4 账号 ACL/RLS、CAS 高并发、实际 Edge JWT/CORS/限流、配额/备份恢复、iPhone Safari 与微信 WebView 真机，以及发布前用户最终审阅。
6. 继续保持 PR #58/#59 Draft；未经额外明确授权，不合并 main、不修改 Pages/Cloudflare 白名单、不应用生产 SQL、不部署 Edge 或发布游戏。
