# 已有普通经营存档 → 私有云档：仅管理员审批的一次性迁移

**未部署，不可直接使用。** 云端经营是服务端权威经济，浏览器本地金币和道具绝不能自行写入云端。

## 授权流程

1. 四个白名单账号中的本人，在开发版页面点击“下载旧档供审核”。
2. 客户端从当前权威 V3 本地存储读取完整 JSON，经严格校验，用 SHA-256 绑定精确 UTF-8 原始字节。本地下载只发生在主动点击后，不上传网络。
3. 可信管理员通过独立安全通道收到文件，人工核验用户身份、存档历史、游戏资源有效性、SHA-256 和游戏规则；没有管理员批准则无法迁移。
4. 管理员在受控、审计的 service_role 环境中向独立授权表写入 user_id、source_sha256、approved_state、approved_by。批准的快照应符合 V3 规则，revision 不低于 1。禁止 Edge 或浏览器创建授权记录。
5. 玩家再次核对本地字节哈希未变化、备份已保存、主动确认后才请求云端领取。领取请求只提交哈希和确认标志，不提交钱包、物品或最终存档。
6. 服务端 JWT 和四账号白名单验证后执行 service-only SQL RPC；同一事务锁定授权与游戏主存档。云端必须尚未玩过该账号，不能覆盖既有正式云端操作日志。
7. 授权成功后记录 consumed_at；网络 ACK 丢失时只返回只读幂等确认，不能重复使用；客户端重新读服务端权威快照。
8. 原有本地文件和浏览器数据不自动清除、覆盖或合并；已开始云端经营的玩家若要切换旧档，必须人工审核处理，禁止自动覆盖。

## 必须完成的发布前验证

独立 PostgreSQL 数据库 RLS/ACL、账号分离、同一授权并发领取、服务器鉴权、已游玩冲突、哈希不匹配、授权不存在、已消费和崩溃恢复；额外验证 Safari/iPhone 与微信 WebView 真机下载及确认。

SQL 仍为 NOT-APPLIED 草稿；正式环境没有部署新 RPC/Edge/网页。未经额外授权绝不能执行生产迁移。
