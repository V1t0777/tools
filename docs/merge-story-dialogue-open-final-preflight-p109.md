# 云屿剧情 P109｜对白打开末端双存档复核（未发布）

## 真实风险与修复
此前对白打开前已复核剧情存档，读取工作台后也会复核一次剧情存档；但在随后组装对白文本、经营回声和选项时，另一标签可能静默改写任一存档，存储事件未必已送达。旧逻辑只检查页面生命周期/事件代次，可能短暂展示与最新经营状态不符的对白。

现在在 `showModal()` 前，针对实际渲染所用的工作台快照执行「工作台→剧情→工作台」只读复核，并在每次读后核验页面生命周期。任何字节不一致或无法读取均取消旧对白；剧情冲突维持原有阻断，工作台冲突给出重新核对提示。不会自动写入、重置或修复任何存档，既有选择/完成时的 Web Locks 与 CAS 继续保留。

## 故障注入与上游协调
- 实际剧情 UI 的 DOM 文本组装期间，另一标签替换有效工作台存档：不得弹出过期对白。
- DOM 文本组装期间，剧情存档原始字节改变但 JSON 仍合法：不得弹出过期对白。
- 末端剧情复核读取期间工作台被替换：末次工作台复核必须拒绝旧对白。
- 三项均要求无写入且普通经营存档不变；保留既有正常对白正向回归。
- 同步普通模式 PR #58 的 P2.65ar 存档导入/导出旧触控修复，三处上游文件经 SHA/路径核对与剧情修改不重叠；保留双父历史，不强推。
