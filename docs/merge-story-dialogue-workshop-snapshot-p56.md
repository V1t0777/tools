# P56 · 剧情对白与真实经营同一快照（未发布）

## 原因与修复
打开主/支线、每日事件对白时重复读取工作台存档，可能恰逢另一标签改动，使经营回声和章节目标由两个不同 revision 构成。本轮统一使用一次验证过的快照生成回声与开启时经营门槛；选择确认前与进入故事写锁后，均重新核对打开对白时的工作台原始字节。另一个标签修改了存档，即使章节没有强制经营目标，也要先重新打开对白，避免从过期剧情反馈提交新选择。

## 验证
新增 P56 专项测试：双次读入竞态、缺失/损坏快照、无经营门槛过期对白阻断、未变化情况下正常保存、UI 单一读取接线。同步上游 PR #58 的 P2.61g 至 P2.61v 独立普通模式安全增量，合并前核对共有祖先后双方变更路径没有交集；不更改原有普通模式逻辑。

## 边界
用户已在 Cloudflare 控制台确认保存「预览分支：无」，仍保留 `[CF-Pages-Skip]` 提交标记作为冗余保护，且无法直接从此连接读取 Cloudflare 设置状态。禁止更改 main、正式部署、白名单、线上 Supabase、Draft 状态；CI 不替代真实 iPhone/微信 WebView 双标签、BFCache 和 Web Locks 兼容性验收。
