# P2.61r 普通模式实际页面的动作版本不变量保护

## 本轮范围

在 `merge/main.mjs` 的同步 `commit(result)` 入口中增加一项**写入前**检查：
成功的玩家动作必须返回独立状态对象，且 `revision` 必须恰好增加 1。
若动作返回空值、非对象、原始状态对象、同版本改写或跳号版本，则将页面标记为
`ACTION_REVISION_INVALID`，展示中文阻断提示，保留现有内存状态及原始存档，
不调用 `persist()`。失败动作原有提示与不写入行为不变。

本次不改变引擎数值、存档结构、计时器、启动迁移、重置或部署配置。
现有合法玩家动作已在引擎中逐次递增 revision；该校验对正常流程透明。

## 验证

`tests/merge-page-action-revision.test.mjs` 使用 Node VM 执行实际页面入口，
覆盖同版本金币篡改、跳号、原对象、异常结果、阻断后不重复求值、
合法单步动作与普通失败动作。还须以该 HEAD 的 GitHub Actions
全仓库回归、静态安全及部署隔离、完整 Git 历史密钥扫描为最终门禁。

## 未解决风险

此保护不等于跨标签原子写入。页面仍采用同步 CAS，启动迁移、
计时器、重置及玩家动作尚未统一切换到 Web Locks；不能把独立事务模块的
测试结果视为实际页面的原子性证明。仍需 iPhone Safari、微信 WebView
及真实跨标签端到端验收；禁止发布、合并或执行线上数据库迁移。
