# 《云屿百物铺》V3 · P2.48 普通模式持锁重置与异常备份边界（未发布）

## 本轮增量
新增 `merge/normal-reset-transaction.mjs`，仅提供**尚未接入页面**的普通模式重置事务边界。复用 P2.45 的同名独占 Web Lock、P2.35 的异常原始字节备份、P2.26 的精确写后读回。无新的锁名、存档格式、网络接口或 UI 行为。

## 事务顺序与保护
1. 仅在 `confirmedReset === true`、原始基线已明确（字符串或明确缺失的 null）、时间和备份策略有效时才尝试持锁。
2. 锁内重新读取 `SAVE_KEY` 并按**完整原始字节**比较。任何跨标签变化均拒绝，不覆盖。
3. 对损坏、未知版本或旧版本存档**强制**在同一锁内备份原始字节并精确读回；对 V3 合法但调用方已知存在异常的存档，调用方必须设置 `requireOriginalBackup: true`。备份槽位冲突、下载封装不可编码或验证失败时，禁止重置。
4. 在备份成功后才生成初始 V3 状态并调用 `commitNormalSnapshot(...,{confirmedReset:true})`。写入及精确读回成功后才向页面返回可发布状态；失败不返回 `state`。
5. 原始键不存在时，仅在调用方明确观测 `expectedRaw:null` 且不要求保留原始备份时允许创建初始存档。重置永不触碰剧情模式命名空间。
6. 若异常重置已创建本地备份但最终写入失败，保留备份不自动清理；同源备份不能替代用户核对的下载文件。

## 专项测试
`node --test tests/merge-normal-reset-transaction.test.mjs` 覆盖未确认、正常重置、损坏原始备份、有效存档强制备份、旧基线、备份槽冲突、备份读回失败、无锁/锁忙、空存档、保存读回失败、非法时钟与策略。CI 的全仓库回归、静态安全与部署隔离、完整 Git 历史密钥扫描必须以本轮提交 SHA 为准。

## 接入与发布限制
`merge/main.mjs` 的现有同步重置、动作、体力计时器、`loadLocal()` 的迁移备份与 `prepareNormalStartup()` 的写入仍未迁移。不可单独将重置接入锁并宣称跨标签原子性；必须先完成所有写入者统一锁与 UI 异步忙碌态。无 Web Locks 的浏览器必须安全拒绝，不允许回退无锁写入。

真实双标签浏览器、iPhone Safari、微信 WebView、真实 PostgreSQL/Edge 均未验收。PR #58/#59 保持 Open/Draft；不合并、不部署、不改正式导航或白名单、不运行线上 Supabase SQL/迁移、不制作美术或作弊后门。
