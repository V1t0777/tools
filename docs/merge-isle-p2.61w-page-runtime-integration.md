# 《云屿百物铺》V3 · P2.61w 普通模式统一持锁页面运行时

**状态：独立研发分支的待接线协调层；未发布、未接入现有 `merge/main.mjs`。**

## 为什么本轮扩大工程幅度

P2.45–P2.61v 已分别完成同名 Web Locks、持锁启动/旧版迁移、游戏动作、体力计时器、异常原始备份、确认重置及异步 UI 单飞的独立单元验证。长期一小时一小修复会延长集成周期，下一阶段必须整合这些经过验证的模块，而不是再复制锁或重复讨论方案。

本轮 **一次性新增 `merge/normal-page-runtime.mjs`**，作为页面接入时唯一的事务协调入口，覆盖正常游戏生命周期和故障恢复。保持现有可试玩页面的同步存档代码不动，以避免在未完成所有四类入口迁移时出现部分持锁、部分无锁的危险中间状态。

## 统一事务契约

- `start({now})`：调用 `prepareNormalStartupWithLock`。旧版备份和迁移、首次存档以及启动时间推进均在同一排他锁下进行，返回的状态须有可信原始存档读回证明。
- `action(operation)`：调用 `commitNormalActionWithLock`，锁内重新读取存档、检查精确原始字节、执行一次同步引擎动作，再验证写入。异常动作、旧版基线和锁忙不允许无锁回退。
- `clock({now})`：同锁执行体力及冷却更新；无变化时零写盘但仍须可信基线读回。
- `reset({confirmed,...})`：独立确认且使用同一锁。若运行时已因异常存档阻断，必须明确提供用户观察过的原始字节，要求异常备份先成功并读回后才能重置。不同模式的存档命名空间严格隔离。
- `reconcile()`：跨标签、恢复前台或 BFCache 可调用的只读核验；较旧版本、同 revision 经济分叉以及损坏/删除状态立即阻断。合法进度推进或安全计时变化才可发布已观察到的存档。
- `invalidate()`：当异步事务在途且页面状态失效时，拒绝向 UI 发布不确定结果，不把可能已写入的存档假定为已经回滚。
- `onVerified(state,raw,kind,receipt)`：唯一的同步 UI 发布接口。传给外部的是克隆状态，避免污染事务内部可信对象。回调出错或返回 Promise 时阻断操作，不谎称保存成功。
- `snapshot()`：只返回克隆，不能通过修改 UI 层引用直接改变运行时持有的可信基线。

## 下一个大阶段（不再碎片化增加辅助工具）

一次性迁移 `merge/main.mjs` 的四种写入路径至此运行时：
1. 在页面初始交互启用前完成持锁初始化；错误时保留只读导出能力，不凭空创建可写游戏进度。
2. 将所有棋盘、委托、仓库、升级、商店等动作及拖拽落点统一使用 `action(operation)`，异步单飞期间禁止重复点击与旧手势。
3. 计时器改由 `clock()` 负责所有写入，并处理背景暂停、跨标签冲突及生命周期失效。
4. 重置改由 `reset()` 进行用户确认、持锁备份与精确读回，不能绕过锁或覆盖新标签进度。
5. 同步更新原先从 `main.mjs` 切取事件处理器的旧测试，保留实质断言，移除只因旧代码排版变化产生的脆弱断言。

提交后必须以 **同一 HEAD** 的全仓库回归、静态安全/部署隔离、完整 Git 历史密钥扫描均成功才算工程验收通过；且必须遵守 `AGENTS.md` 的安全检查要求。
