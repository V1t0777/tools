# P8：剧情工作台仓库解堵交互（未发布）

## 背景与边界
P7 的 44/56 高占用自动策略并不等于真实玩家没有卡关。原剧情工作台已使用完整 V3 引擎，但没有暴露引擎支持的 `storeItem` 与 `withdrawItem`，因此玩家无法利用现有仓库腾出棋盘空间。本轮只完善**剧情工作台**界面，不改变核心经济、生产概率、仓库升级规则、普通模式或部署名单。

## 实际交互
- 点击棋盘中的一件材料，选择「收纳选中材料」；生产器不可入库，仓库满时按钮禁用。
- 显示棋盘占用（x/56）与仓库占用（x/容量），按现有 `state.warehouse.capacity` 渲染槽位（初始 4 格）；点击已占用槽位可取回，棋盘满时取回禁用。
- 棋盘满但仓库有空位时明确提示收纳；两者均满时提示合成相同链与相同等级的材料。仓库物品必须先取回才能交付订单。
- 使用原有 `commit` → `writeStoryWorkshop` CAS 写入，沿用多标签页冲突与损坏存档保护。只访问 `STORY_WORKSHOP_KEY`，与普通模式资源不互通。
- 使用 DOM `textContent` 构建仓库按钮，不使用 HTML 拼接；移动端两列按钮、最小 48px 点击高度，宽屏四列，支持深色、键盘焦点及减少动画偏好。

## 验证
- 新增 `tests/merge-story-warehouse-ui.test.mjs`：真实存入/取回/订单交付、存档往返隔离、移动 UI/安全契约。
- 需由最终 SHA 的 GitHub Actions 完成 Node 全仓库回归、`bash scripts/security-check.sh` 和完整历史密钥扫描。静态契约不能替代 iPhone 实机的点击、屏幕阅读器与安全区验收。
